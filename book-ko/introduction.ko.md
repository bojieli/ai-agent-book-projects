# 들어가며 {.unnumbered}

2025년 8월부터 10월까지 저는 투링(Turing)의 ‘AI 에이전트 부트캠프’에서 기술 강의를 진행했습니다. 강의는 하나의 질문을 중심으로 구성했습니다. 경험과 직관에 따른 반복적 시행착오가 아니라 설명 가능하고 검증 가능하며 재사용 가능한 공학 원칙으로 AI 에이전트를 어떻게 설계할 것인가? 따라서 데모를 실행하는 것은 종착점이 아니었습니다. 특정 아키텍처를 택하는 이유, 그에 따른 능력의 경계, 각 설계 결정이 수반하는 절충까지 함께 살펴보았습니다. 이 책은 당시 강의 자료와 관련 실험을 체계적으로 정리하고 확장해 재구성한 결과물입니다.

책을 만드는 과정 자체도 인간–에이전트 협업을 실천한 실험이었습니다. 구상부터 최종 원고까지 저는 주로 **위스퍼 코딩(whisper coding)**, 즉 받아쓰기를 통한 협업 방식으로 Pine의 음성 에이전트와 조사와 문서 수정을 진행했습니다. 제가 장의 개요를 말하면 에이전트가 관련 자료를 검토하고 초안을 작성했습니다. 이후 수강생 피드백을 반영해 논증, 사례, 실험을 여러 차례 검증하고 수정했습니다. 음성은 생각을 외부화하는 비용을 줄이고, 질문 설정에서 자료 탐색, 작성, 검증으로 이어지는 주기를 단축합니다. 따라서 이 책은 에이전트를 설명하는 데 그치지 않고 에이전트가 깊이 참여한 지식 생산 방식도 기록합니다.

2025년 초 DeepSeek R1 공개 이후 AI 연구와 산업 실천의 초점은 기반 모델의 능력에서 에이전트의 체계적 배치로 넓어졌습니다. 모델 측에서는 에이전틱 강화학습이 도구 사용과 환경 상호작용을 파라미터에 내재화하며 프로그래밍, 수학적 추론, Computer Use의 범용 능력을 강화하고 있습니다. 제품 측에서는 Manus, Claude Code, OpenClaw 같은 범용 에이전트가 인간–컴퓨터 상호작용을 바꾸고 ‘코드 생성 + 파일 시스템’을 중요한 시스템 아키텍처로 만들었습니다.

강의에서 정리한 에이전트 아키텍처 원칙을 다시 검토하면, 모델과 제품이 빠르게 변해도 이 원칙들은 안정적인 설명력을 유지한다는 점을 확인할 수 있습니다. 업계에서 나중에 Skill, harness, loop engineering 같은 용어를 널리 쓰게 되었지만, 그에 해당하는 공학적 실천은 대개 더 이른 시점에 나타났습니다. 개념은 실천의 출발점이 아니라 다양한 실천 경험을 귀납한 결과입니다. 즉 실천이 먼저이고 명명은 나중입니다.

이 원칙들은 장기적이고 위험도가 높은 시스템을 엔지니어링한 경험에서 주로 나왔습니다. Pine AI의 Chief Scientist로서 저는 팀과 함께 Pine을 개발해 에이전트가 사용자를 대신해 사람과 소통하고 요금 협상, 환불 분쟁, 구독 취소처럼 실제 경제적 이해가 걸린 복잡한 일을 처리하도록 했습니다. 이런 일은 오래 지속되고 여러 차례 협상을 거치며, 한 번의 잘못된 단계도 실제 손실을 낳을 수 있습니다. 신뢰성, 안전성, 감사 가능성에 대한 엄격한 요구가 이 책의 아키텍처 원칙을 형성했습니다.

- 스킬이 유행어가 되기 훨씬 전부터 저희는 동적 프롬프트 로딩으로 끝없이 늘어나는 프롬프트를 통제하고, 명령줄 실행 도구로 끝없이 늘어나는 도구 목록을 통제했으며, 시스템 상태 표시줄을 통해 에이전트가 실행 환경과 사용자의 시간, 자신의 작업 상태를 인식하게 했습니다.
- 하네스가 유행어가 되기 훨씬 전부터 저희는 Claude Code와 같은 방식으로 불안정한 도구 호출, 환각, 위험한 작업, 권한 없는 작업, 무시된 지시를 처리했습니다.
- 루프 엔지니어링이 유행어가 되기 훨씬 전부터 저희는 이 책에서 제안자-검토자 방식이라고 부르는 방법으로 모델이 업무를 너무 일찍 끝났다고 선언하지 못하게 했습니다.

이러한 방법은 Pine만의 것이 아닙니다. 많은 모델·에이전트 팀이 유사한 문제를 해결하는 과정에서 서로 비슷한 공학 방법을 독립적으로 형성했습니다. 이러한 수렴은 그 방법들이 에이전트 시스템의 공통 제약을 반영한다는 뜻입니다. 이러한 인식을 바탕으로 저는 2025년 투링에서 ‘AI 에이전트 부트캠프’를 열었고, 2024–2026년 중국과학원대학교에서 실습형 AI 에이전트 강의를 계속했습니다. 이 책을 오픈 소스로 공개한 것도 재사용 가능한 지식과 경험이 더 많은 연구자와 엔지니어에게 활용되길 바라기 때문입니다.

**실천이 먼저이고 명명은 나중입니다.** 기업용 에이전트 개발에서 이는 실천이 개념의 확산에 항상 뒤처져서는 안 된다는 뜻입니다. 어떤 용어가 업계의 공통 언어가 되었을 때는 그 용어가 가리키는 문제가 선행 시스템에서 오랜 기간 탐구되었을 가능성이 큽니다. 이러한 문제를 더 빨리 식별하고 해결하려면 두 가지 조건이 필요합니다.

**첫째, 에이전트의 능력 상한에 충분히 높은 요구를 부과하는 실제 사업을 선택하고 실제 피드백을 지속적으로 확보해야 합니다.** Pine의 한 업무는 몇 시간에서 몇 주까지 지속될 수 있으며, 여러 이해관계자와의 반복적인 조율, 장시간 통화, 복잡한 양식 작성, 여러 차례의 이메일 왕복이 필요할 수 있습니다. 동시에 핵심 숫자의 정확성과 작업의 통제 가능성을 보장하고 사용자의 이익을 지켜야 합니다. 이처럼 복잡한 환경은 모델 능력과 사업 요구 사이의 간극을 계속 드러내고, harness를 구축해 모델이 아직 독립적으로 처리하지 못하지만 사업상 반드시 필요한 문제를 체계적으로 해결하도록 합니다. 반면 다음 모델 업그레이드로 쉽게 충족되는 요구만 있다면 안정적인 시스템 설계 원칙을 축적하기 어렵습니다.

**둘째, 체계적인 평가(Evaluation) 메커니즘을 구축해야 합니다.** 평가가 없으면 한 번의 변경이 가져온 향상이 설계 자체에서 비롯된 것인지, 무작위 변동에서 온 것인지 판단할 수 없습니다. 평가는 에이전트의 반복 개선을 경험적 판단에서 비교 가능하고 재현 가능한 공학 과정으로 전환하며, 과학적 방법으로 시스템을 개발하는 토대가 됩니다. 7장에서 이 방법을 자세히 다룹니다.

기반 모델이 아무리 발전하고 제품의 형태가 아무리 달라져도 성공적인 에이전트 시스템은 거의 모두 같은 아키텍처 패턴을 따릅니다. 우연이 아닙니다. **훌륭한 설계 원칙은 모델의 반복 주기보다 오래 지속되어야 합니다.** 특정 모델의 사용법이 아니라 지능형 시스템이 세계와 상호작용하는 근본 패턴을 설명하기 때문입니다.

튜링상 수상자이자 강화 학습의 아버지인 리처드 서튼은 우주의 진화가 먼지, 별, 생명, 에이전트(원래 표현은 ‘설계된 존재(designed entities)’)라는 네 단계를 거쳤다고 말한 적이 있습니다. 생물학적 진화는 무작위 돌연변이와 자연 선택으로 이루어지는 맹목적 과정입니다. 대부분의 생물은 자신의 작동 원리를 이해하지 못하며 스스로 생명을 설계하거나 다시 만들 수도 없습니다. 그러나 에이전트는 우주 진화의 역사에서 완전히 새로운 존재입니다. 한 프로그래머가 또 다른 프로그래머를 만들고 그 프로그래머가 다시 다음 프로그래머를 만들듯, 코드를 생성하여 스스로 부트스트랩하고 진화할 수 있습니다. 다시 말해 에이전트는 자신의 작동 메커니즘을 이해하고 목표가 주어지면 완전히 새로운 에이전트를 만들며, 심지어 자신을 개선할 수도 있습니다. 이 책의 사명은 여러분이 이러한 창조의 원리를 이해하고 익히도록 돕는 것입니다.

이 책의 핵심 공식은 한 문장입니다. **에이전트 = LLM + 컨텍스트 + 도구**. 세 요소 모두 빠질 수 없습니다.

![그림 0-1: 에이전트 = LLM + 컨텍스트 + 도구](images/fig0-1.svg)

더 직관적으로 표현하면 **두뇌 + 눈 + 손발**입니다. 두뇌(LLM)는 사고와 의사 결정을 담당하고, 눈(컨텍스트)은 에이전트가 어떤 정보를 볼 수 있는지 결정하며, 손발(도구)은 에이전트가 무엇을 할 수 있는지 결정합니다. (엄밀히 말하면 ‘눈’은 대략적인 비유입니다. 컨텍스트에는 환경 정보와 대화 기록뿐 아니라 도구 정의도 포함되므로 에이전트가 ‘보는’ 정보에는 ‘어떤 손발을 사용할 수 있는가’도 들어갑니다. 이 비유의 목적은 핵심 직관, 즉 컨텍스트가 모델이 인식할 수 있는 모든 정보라는 점을 전달하는 데 있습니다.)

강화 학습에 익숙한 독자라면 이 세 요소를 강화 학습의 형식 언어로 대응시킬 수도 있습니다. 구체적으로 LLM은 정책(Policy), 컨텍스트는 관측 공간(Observation Space), 도구는 행동 공간(Action Space)에 해당합니다. 세 표현은 추상화 수준만 다를 뿐 같은 대상을 가리킵니다.



## 책의 구성 {.unnumbered}

이 책의 열 개 장은 서로 이어지는 두 가지 질문을 중심으로 구성됩니다(그림 0-2). **제1부 “에이전트를 어떻게 구축할 것인가”**는 1~6장으로, 기초 개념에서 컨텍스트, 메모리와 지식, 도구, 코딩 에이전트, 관찰·행동 공간의 확장으로 나아갑니다. **제2부 “에이전트의 능력을 어떻게 향상할 것인가”**는 7~10장으로, 평가를 통해 측정 가능한 피드백을 먼저 확립한 뒤 모델 사후 학습, 운영 경험에 기반한 지속적 진화, 멀티 에이전트 협업을 통해 모델 파라미터·개별 시스템·집단 시스템 수준에서 능력을 확장합니다.

![그림 0-2: 책의 구조 — 에이전트 구축과 능력 향상](images/fig0-2.svg)

- **1장(에이전트 기초)**은 실제 에이전트 제품 몇 가지를 통해 에이전트를 직관적으로 이해하는 데서 시작합니다. 이어서 에이전트의 핵심 공식을 구현 계층의 LLM + 컨텍스트 + 도구, 직관 계층의 두뇌 + 눈 + 손발, 학술 계층의 정책 + 관측 공간 + 행동 공간이라는 세 수준에서 자세히 살펴봅니다. 실험을 통해 ‘생각 → 행동 → 관찰’을 반복하는 ReAct 루프의 작동 방식을 분석하고, 한 업무 안에서 이루어지는 컨텍스트 적응, 여러 업무에 걸친 외부 산출물 업데이트, 학습 주기 동안의 매개변수 업데이트를 구분합니다. 마지막으로 워크플로부터 자율 에이전트까지 이어지는 오케스트레이션 설계 패턴을 다루어 이후 장을 위한 통합 개념 프레임워크를 세웁니다.
- **2장(컨텍스트 엔지니어링)**은 이 책에서 가장 중요한 장으로, 에이전트의 ‘눈’인 컨텍스트를 체계적으로 설명합니다. API 메시지 구조와 에이전트의 핵심 루프에서 출발해 ‘컨텍스트는 메시지 목록이다’라는 토대를 세운 다음, LLM 추론 과정에서 과거 계산 결과를 재사용하는 KV 캐시의 기본 원리를 살펴봅니다. 이어서 프로세스 중심 설계, 도구 설명, 비즈니스 규칙 개선을 포함한 프롬프트 엔지니어링, 프롬프트 인젝션 공격과 방어, 에이전트 스킬의 주문형 로딩 메커니즘, 에이전트 상태 표시줄 기술, 컨텍스트 압축 전략을 다룹니다. 각 용어의 완전한 정의는 본문에서 처음 등장할 때 제공합니다.
- **3장(사용자 메모리와 지식 베이스)**은 컨텍스트 관리를 세션을 넘나드는 지속적 지식 시스템으로 확장합니다. 이를 통해 에이전트는 현재 대화를 기억할 뿐 아니라 여러 대화에 걸쳐 지식을 축적하고 검색할 수 있습니다. 사용자 메모리를 위한 네 가지 점진적 전략, 모델이 답변을 생성하기 전에 관련 문서를 검색하는 RAG(Retrieval-Augmented Generation, 검색 증강 생성)의 전체 기술 스택, 다양한 텍스트 검색 방식과 순위 최적화, 멀티모달 정보 추출, 더 발전된 지식 구성 방식, 그리고 에이전트가 검색 시점과 대상을 자율적으로 결정하는 에이전틱 RAG를 다룹니다.
- **4장(도구)**은 에이전트와 외부 세계를 잇는 다리를 살펴봅니다. 도구는 에이전트의 ‘손발’로 작동하여 웹 검색, API 호출, 데이터베이스 조작 등을 가능하게 합니다. 도구 상호운용성 표준인 MCP와 인식, 실행, 협업, 이벤트 트리거, 사용자 커뮤니케이션이라는 다섯 가지 도구 범주의 설계 원칙을 소개하며, 특히 실행 도구의 보안 메커니즘을 강조합니다. 이벤트 트리거, 사용자 커뮤니케이션, 비동기 런타임은 6장에서 자세히 다룹니다.
- **5장(코딩 에이전트와 코드 생성)**은 코딩 에이전트와 파일 시스템의 결합이 모든 범용 에이전트의 핵심 기술 기반이라고 주장합니다. OpenClaw 아키텍처를 중심축으로 삼아 코딩 에이전트의 워크플로와 구현 기법을 분석하고, 사고 보조와 지식 베이스 구축부터 새로운 도구의 동적 생성과 에이전트 부트스트래핑까지 프로그래밍을 넘어선 코드 생성의 폭넓은 가치를 보여 줍니다.
- **6장(상호작용: 관찰 공간과 행동 공간의 확장)**은 에이전트와 환경의 상호작용을 **모달리티**와 **시간성**이라는 두 차원에서 다룹니다. 비동기·이벤트 기반 시스템은 외부 이벤트를 지속적으로 수신하고 응답하게 하며, 음성은 인식·추론·생성을 실시간 동작으로 전환하고, Computer Use는 행동 공간을 그래픽 인터페이스로, 로보틱스는 물리 환경으로 확장합니다. 네 영역은 기동, 안전 지점, 취소, 선점, 빠른 경로와 느린 경로의 분리라는 시스템 프리미티브를 공유합니다.
- **7장(에이전트 평가)**은 과학적인 평가 방법론을 구축합니다. 두 가지 핵심 패러다임인 도구 호출과 인간-컴퓨터 상호작용, 그리고 장 마지막에서 별도로 다루는 시뮬레이션 환경을 포함한 평가 환경, 데이터셋 설계 원칙, LLM-as-a-Judge 자동 평가, 평가 기반 모델 선택, 평가 결과를 시스템 개선으로 전환하는 완전한 폐루프를 다룹니다.
- **8장(모델 사후 학습)**은 두 가지 사후 학습 기술을 깊이 있게 다룹니다. 라벨이 있는 데이터로 예제를 따르도록 모델을 가르치는 지도 미세 조정(SFT, Supervised Fine-Tuning)과, 시행착오와 보상 피드백을 통해 모델이 자율적으로 개선되게 하는 강화 학습(RL, Reinforcement Learning)입니다. ‘SFT는 암기하고 RL은 일반화한다’, ‘알고리즘보다 데이터와 환경이 중요하다’라는 중심 논지를 따라 사전 학습/SFT/RL의 전체 구도, 고전 강화 학습 이론, 이진 보상과 과정 보상부터 ‘결과를 보상하고 과정을 제약하는’ 검증된 경로 페널티까지의 보상 신호 설계, 단일 턴 및 다중 턴 강화 학습 알고리즘, 샘플 효율 최적화 같은 최전선 주제를 다룹니다.
- **9장(에이전트의 지속적 진화)**은 에이전트의 운영 경험을 다음 버전의 능력으로 전환하는 방법을 연구합니다. 먼저 환경 결과, 프로세스 규칙, LLM 루브릭으로 구성되는 학습 신호를 확립합니다. 이어서 지식 문서, 프롬프트와 스킬, 프로그램과 하네스, 모델 매개변수라는 네 가지 업데이트 매체를 비교하고, 마지막으로 후보 버전 검증, 카나리 릴리스, 롤백, 장기 통합을 논의합니다.
- **10장(멀티 에이전트 협업)**은 개별 에이전트의 능력에서 시스템 수준의 협동으로 범위를 넓혀, 여러 에이전트가 업무를 나누고 협력하는 방법을 다룹니다. 공유/독립 컨텍스트 × 동료/관리자/탈중앙화 구조라는 분류 프레임워크를 체계적으로 제시하고, 번역 에이전트와 전화–컴퓨터 협동 에이전트 사례를 통해 아키텍처 설계를 보여 주며, 에이전트 사회와 에이전트 경제의 잠재적 발전 방향을 논의합니다.

에이전트 기술은 여전히 빠르게 발전하지만 **훌륭한 아키텍처 설계 원칙은 시간을 견디는 힘이 있습니다.** 설계의 ‘왜’를 익히면 기술의 파도가 밀려와도 명확한 판단력을 유지할 수 있습니다. 이 책이 여러분의 AI 에이전트 구축 여정에 든든한 안내서가 되기를 바랍니다.
