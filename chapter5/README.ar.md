# الفصل الخامس · وكيل البرمجة وتوليد الشفرة

> الشفرة «أداة تستطيع إنشاء أدوات جديدة»، ولذلك تمثل قدرة فوقية للوكيل العام. ويستخدم الفصل وكيل برمجة جاهزًا للإنتاج لشرح التنفيذ الكامل لهذه القدرة.

← [العودة إلى الملف التمهيدي الرئيسي](../docs/ar/README.md) · 📖 [قراءة نص الفصل](../book-ar/chapter5.ar.md)

## المشاريع المصاحبة

| التجربة | المشروع | النوع | الوصف |
| :--: | --- | :--: | --- |
| 5-1 | [الشفرة للرياضيات](code-for-math/) | ✅ | يقارن بين سلسلة أفكار نصية خالصة وحل مدعوم بالشفرة، باستخدام النموذج نفسه ومجموعة المسائل نفسها. وفي النمط الثاني تُصاغ المسائل بلغة Python باستخدام sympy وnumpy وscipy، وتُنفذ داخل بيئة معزولة، فيحل الحساب الدقيق محل الحساب الذهني المعرض للخطأ ويرفع الدقة بوضوح. |
| 5-2 | [الشفرة للمنطق](code-for-logic/) | ✅ | يحول ألغاز «الفرسان والأوغاد» إلى مسائل إرضاء قيود (CSP). ويستخدم الوكيل `python-constraint` لتعريف المتغيرات والقيود ثنائية الاتجاه ثم يستدعي الحل، ويقارن دقة الاستدلال باللغة الطبيعية بدقته عند الاستعانة بالشفرة. |
| 5-3 | [قواعد مضمّنة في الشفرة للنماذج الصغيرة](small-model-codified-rules/) | ✅ | تجربة مضبوطة تستند إلى سيناريو خدمة عملاء شركات الطيران في τ-bench. وبعد نقل سياسات العمل المعقدة، مثل قواعد رد الأموال، من موجّهات اللغة الطبيعية إلى الشفرة والأدوات، يتحسن بوضوح معدل إنجاز النموذج الصغير والتزامه بالسياسة. ويستطيع التحقق داخل الأداة اعتراض افتراضات النموذج الخاطئة أثناء التشغيل. |
| 5-4 | [من الورقة البحثية إلى العرض التقديمي](paper-to-ppt/) | ✅ | يعيد صياغة إنشاء عرض PPT بوصفه مسألة توليد شفرة: يكتب الوكيل المقترِح عرضًا باستخدام Slidev ‏(Markdown وHTML)، ثم يصيّر الوكيل المراجع كل صفحة إلى PNG ويستخدم نموذجًا بصريًا لفحص مشكلات التخطيط، ويكرر المراجعة وفق ملاحظات منظمة. ويخفض هذا التقسيم الثنائي ذروة استهلاك السياق بوضوح. |
| 5-5 | [من الورقة البحثية إلى الفيديو](paper-to-video/) | ✅ | يبني على مشروع «الورقة إلى العرض»، فينشئ نصًا سرديًا طبيعيًا لكل شريحة، ويركب الصوت باستخدام TTS، ثم يستعمل ffmpeg لمزامنة صور الشرائح مع الصوت وإنتاج فيديو تفسيري. |
| 5-6 | [تحرير الفيديو](video-edit/) | ✅ | يحدد الوكيل المشهد المطلوب في فيديو متعدد المشاهد عبر تموضع بصري من مرحلتين، يبدأ بمسح تقريبي ثم قراءة دقيقة للإطارات. وبعد القص يستخرج الوكيل المراجع إطارات رئيسية للتحقق من النتيجة ويكرر العملية عند الحاجة. |
| 5-7 | [محلل السجلات التكيفي](adaptive-log-parser/) | ✅ | نظام لتحليل السجلات يتطور ذاتيًا. فعند ظهور تنسيق جديد لا يستطيع تحليله، يرسل العينة الفاشلة ورسالة الخطأ إلى وكيل توليد الشفرة لإنشاء دالة `parse`. وبعد اجتياز الاختبارات، تُحدَّث الدالة وتُسجَّل في محرك التحليل من دون تدخل بشري. |
| 5-8 | [تشخيص السجلات](log-diagnosis/) | ✅ | يقرأ وكيل التشخيص مسارات HTTP حقيقية ووثائق البنية وبيانات PRD، ويولّد اختبارات انحدار ويعيد تشغيلها قبل الإصلاح وبعده؛ وينشئ التشغيل الرسمي Issue حقيقية عبر خادم GitHub MCP الرسمي مع حفظ إيصالات منزوعة بيانات الاعتماد. |
| 5-9 | [نموذج ديناميكي](dynamic-form/) | ✅ | عند نقص معلومات الطلب، ينشئ الوكيل نموذج HTML مستقلًا يجمع كل البيانات المطلوبة دفعة واحدة بدل طرح الأسئلة تباعًا. وتجمع الواجهة الإجابات في JSON وتعيدها إلى الوكيل لمتابعة المهمة. |
| 5-10 | [وكيل ERP](erp-agent/) | ✅ | يحول الاستعلامات الصينية بلغة طبيعية إلى SQL ينفذ داخل قاعدة البيانات، ثم يعرض الجدول الناتج مباشرة. وتقوم الفكرة على تمرير عبارة SQL بدل نقل البيانات نفسها، مما يوفر الرموز ويجنب أخطاء الحساب اليدوي، حتى مع نتائج تضم عشرات الآلاف من الصفوف. |
| 5-11 | [واجهة محادثية](conversational-ui/) | ✅ | يصف المستخدم تخصيصات الواجهة، كاللون والخط والنص والتخطيط، بلغة طبيعية. ويعثر الوكيل على شفرة واجهة React ويعدلها، ثم يطبق Vite التغييرات فورًا عبر استبدال الوحدات الساخن (HMR)، بما يدعم جولات متتابعة من التخصيص. |
| 5-12 | [كائنات البيانات المضمّنة للصلاحيات](permission-embedded-data-objects/) | ✅ | مخزن كائنات فوق PostgreSQL يفرض التفويض والتحقق وسلامة المراجع والتفاعلات المضبوطة تحت شفرة التطبيق المولّدة ديناميكيًا. |
| 5-13 | [وكيل إنشاء الوكلاء](agent-creator/) | ✅ | وكيل برمجة وصفية يقارن تعديل تطبيق مرجعي متحقق منه بإنشاء وكيل من الصفر؛ ويُترجم المساران ويُختبران ويُشغّلان عبر واجهة Kimi K3 حقيقية لاستدعاء الأدوات. |
