> 版本：**v2.3**（相对 v2.2：生产硬化 OIDC/JWKS、KMS SPI、SIEM SPI、on-prem moderation；Dual-LLM opt-in MVP + 会话图；外部红队真 subprocess；业务 VK 第二租户）

## 1. 一句话架构

**Centralized Safety Gateway（VK）+ 四层防线 + 不可变 policy_binding + 加密 Vault + ModelProxy + L4 工具风险引擎（黑白名单 / 危险操作识别 / 全量审计 / HITL）+ 治理台 + 红队闭环 + SIEM。**

## 2. Online 平面

```
Client ─ Bearer vk_xxx ─▶ SafetyGateway
    ├─ AuthN/Z (VK → tenant/app/scopes/budget)
    ├─ RateLimit / Budget (Redis)
    ├─ PolicyEngine.resolve(policy_binding)
    ├─ L1 Input Scanners (+ Encrypted Vault)
    ├─ L2 Pre-inference (system hash, model allowlist, tool bind)
    ├─ ModelProxy (failover, OpenAI-compatible)
    ├─ L3 Output Scanners (+ deanonymize / schema)
    ├─ L4 ToolRuntime
    │     ① Global/App denylist（硬禁）
    │     ② App allowlist（默认拒绝）
    │     ③ effect_cap
    │     ④ ToolRiskClassifier（参数级危险操作识别）
    │           → allow | alert_only | confirm_only | block
    │     ⑤ Execute（仅 allow）| ApprovalWorkbench（confirm_only）
    │     ⑥ Audit + SIEM（无论放行/拒绝）
    └─ Audit hash-chain
```

## 4. 工具风险治理（v2.1 新增权威节）

### 4.1 业务原则

1. **默认拒绝**：未进应用白名单的工具不可调用。  
2. **黑名单优先于白名单**：全局/租户/应用 denylist 命中 → 永久 `block`，白名单无法覆盖。  
3. **同工具不同参数 ≠ 同风险**：必须做**操作级**识别，不能只看 tool_id。  
4. **全量审计**：allow / deny / confirm 均落 `tool.*` 事件 + 参数摘要（脱敏）+ 风险分。  
5. **临时例外**：仅经 ApprovalWorkbench，带期限与双人（critical），写入审计。

### 4.2 三层名单

| 层 | 配置 | 语义 |
|----|------|------|
| 平台全局黑名单 | `platform_tool_denylist` | 行内硬禁（如 `shell_exec`） |
| 应用黑名单 | `tool_denylist`（policy_binding） | 本应用额外禁掉的工具 |
| 应用白名单 | `tool_allowlist` | 本应用允许发现/调用的工具 |

版本纪律：白名单只能收紧（子集）；黑名单只能加严（超集）。见 ADR-019。

### 4.3 ToolRiskClassifier（危险操作识别）

输入：`tool_id` + `arguments` + `policy_binding`  
输出：`op_risk_tier`（low|medium|high|critical）+ `decision` + `reason_codes[]` + `matched_rules[]`

规则类型（规则优先，可扩展分类器 SPI）：

| 规则 | 示例 |
|------|------|
| 收件人/域名 | `send_email.to` 不在 `email_domain_allowlist` → high/confirm 或 block |
| URL 主机 | `fetch_url.url` 命中外网/IP → medium+ |
| 金额阈值 | `transfer.amount` ≥ N → critical/confirm |
| 关键字 | 参数含 `rm -rf`、生产表名 → block |
| 工具固有风险 | 工具本身 `production_effect=production` 且无例外 → 至少 confirm（按 risk_tier） |

决策映射（默认）：

| op_risk_tier | 默认 decision |
|--------------|---------------|
| low | allow（可 alert_only） |
| medium | alert_only 或 confirm_only（按应用） |
| high | confirm_only |
| critical | block 或 confirm_only（金融默认 confirm + 双人） |

### 4.4 L4 流水线（权威顺序）

```
Constrain(schema) → Denylist → Allowlist → effect_cap
  → ToolRiskClassifier → (block | confirm_only | allow)
  → Execute? → Audit(always)
```

禁止：Scanner/LLM 直连工具；禁止跳过 Classifier 直接 Execute。
