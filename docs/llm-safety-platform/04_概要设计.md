# LLM 安全平台｜概要设计（HLD）

> 版本：**v2.0 Production Cut** · 对齐架构基线 **v2.0**  
> 上位：[03_架构基线.md](./03_架构基线.md) · 下级：[05_详细设计.md](./05_详细设计.md) · ADR：[DECISIONS.md](./DECISIONS.md)

---

## 1. 设计目标

1. **统一控制点**：所有 LLM 流量经 FastAPI Safety Gateway，策略一处变更、处处生效（ADR-002）
2. **可运营**：VK 鉴权、限流预算、决策可解释、控制台可治理
3. **可合规**：哈希链审计 + OTel/SIEM；PII 经 Vault 不出可信域（ADR-007 / ADR-017）
4. **可扩展**：Scanner `shim|onnx|remote`；ModelProxy 多上游（ADR-014）
5. **可发布**：ReleaseEvaluator 阻塞发布；critical 双人审批（ADR-009 / ADR-018）

### 非目标

模型训练、公有云多租户计费 SaaS、跨云多活、替换纪要君主链路。

## 2. 逻辑架构

| 层 | 模块 | 说明 |
|----|------|------|
| 接入 | Gateway + VK / OIDC | Bearer `vk_xxx`；Admin 走 OIDC+RBAC（ADR-013 / ADR-015） |
| 控制 | PolicyEngine | PG 持久化 binding；只追加版本（ADR-005） |
| 防护 | ScannerOrchestrator L1–L3 | 规则优先；模式 shim/onnx/remote |
| 执行 | ModelProxy + ToolRuntime / HITL | 路由；**L4 黑白名单 + 危险操作识别 + 全量审计**（ADR-019）；confirm_only 审批 |
| 数据 | PG + Redis + Vault | 策略/审计/审批；限流预算；加密脱敏（ADR-012） |
| 治理 | Console + RedTeam | 策略/VK/审计/审批/红队；Offline 门禁闭环 |
| 观测 | OTel + Prometheus + SIEM | 指标/链路/哈希链事件外发 |

## 3. 部署架构（目标态）

```text
Clients ─ VK ─▶ LB ─▶ Safety Gateway (FastAPI, N 副本, K8s)
Admin   ─ OIDC ─▶ Console (React) ─▶ /v1/admin/* /v1/approvals/* /v1/redteam/*

Gateway ─┬─ PostgreSQL（policy / audit / approvals / vault / redteam）
         ├─ Redis（rate limit / budget / session cache）
         ├─ ModelProxy → 内网/专线上游 LLM
         └─ OTel Collector → Prometheus / SIEMSink

Offline Workers（promptfoo / garak / PyRIT）
  → redteam_runs → ReleaseEvaluator → policy.published
```

本地：`deploy/docker-compose.yml`。行内：`deploy/helm/llm-safety-platform/`（ADR-016）。

## 4. 质量属性

| 属性 | 目标 | 手段 |
|------|------|------|
| 延迟 | L1 规则路径 P99 ≤ 50ms；含轻量分类器 P99 ≤ 200ms；网关开销（不含上游 LLM）P99 ≤ 80ms | 规则优先、Scanner 超时、Redis 缓存 |
| 可用性 | Gateway 99.9% | 无状态副本；依赖降级按 risk_tier（ADR-006） |
| 安全默认 | high/critical fail-closed | ADR 锁定 |
| 可审计 | 100% 请求有 SafetyDecision + 哈希链 | 同步写 ledger；SIEM emit（ADR-017） |
| 隔离 | 租户级 Vault/策略/VK | tenant_id 分区键 |
| 成本 | Token/Scanner 可配额 | Redis BudgetTracker + VK budget |

## 5. 容量粗模

| 参数 | 初值 |
|------|------|
| 接入应用数 | 50 |
| 日请求 | 5e5（设计 ×1.3 → 6.5e5） |
| 高峰 QPS | 200（设计 300） |
| 含 LLM/ONNX 分类器比例 | ≤15%（其余纯规则 / shim） |
| Gateway 副本（设计） | 3（每副本约 100–150 QPS 规则路径） |
| PG | 主从；审计表按月分区可调 |
| Redis | 单分片起步；限流键 TTL 对齐窗口 |
| 红队日任务 | 2 全量探针集 / 租户抽样 |

## 6. 跨切面

- **鉴权**：VK（业务流量）+ OIDC（控制台）；角色 Admin / Security / AppOwner / Auditor
- **密钥**：Virtual Keys；上游 Provider Key 仅 ModelProxy 持有，永不下发（ADR-013）
- **可观测**：decision / reason_code / latency / scanner_id / vk_id；哈希链 prev_hash
- **变更**：策略发布必须过 ReleaseEvaluator；critical 双人（ADR-018）；见 [06](./06_控制成熟度与发布门禁.md)

## 7. 模块依赖（允许方向）

```
gateway → auth(vk), policy, scanners, vault, providers, tool_runtime, approvals, events, observability
scanners → vault (redact only)
tool_runtime → connectors (SPI)
approvals → tool_runtime (resume execute)
eval / redteam → 全部（只读契约 + 门禁）
console → /v1/admin|approvals|redteam（OIDC）
providers ↛ tool_runtime
scanners ↛ providers（除 SafetyClassifier 显式调用）
```
