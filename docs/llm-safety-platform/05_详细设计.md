## 1. API 清单

鉴权：业务接口 `Authorization: Bearer vk_xxx`（ADR-013）；Admin/审批/红队走 OIDC JWT/JWKS + RBAC（ADR-015/025）。`OIDC_REQUIRED=1` 时校验失败一律 401。

### 1.1 健康与兼容

| Method | Path | 说明 |
|--------|------|------|
| GET | `/healthz` | 存活；依赖探测可选 `?ready=1`（PG/Redis） |
| POST | `/v1/chat/completions` | OpenAI-compatible；内部走同一 Gateway 编排 |

### 1.2 安全业务

| Method | Path | 说明 |
|--------|------|------|
| POST | `/v1/safety/chat` | 同步护栏 + 可选模型调用 |
| POST | `/v1/safety/scan` | 仅扫描，不调模型 |
| POST | `/v1/tools/execute` | 显式 L4（已持有 tool_calls 时） |

**`POST /v1/safety/chat` Request（摘要）**

```json
{
  "messages": [{"role": "user", "content": "..."}],
  "tool_calls": [{"name": "send_email", "arguments": {}}],
  "invoke_model": true,
  "session_id": "sess_optional",
  "rag_chunks": [],
  "system_prompt": ""
}
```

租户/应用由 VK 解析；`session_id` 驱动会话图（ADR-027）；`SAFETY_DUAL_LLM=1` 时走 Dual-LLM 路径。

**Response（摘要）**：`request_id`、`decision`、`policy_binding_id`、`policy_version`、`messages`、`model_output`、`tool_results`、`approval_id?`、`safety_decision`（见 07）。

### 1.3 Admin（OIDC）

| Method | Path | 角色 | 说明 |
|--------|------|------|------|
| GET | `/v1/admin/policies` | AppOwner+ | 列 binding（含历史版本） |
| GET | `/v1/admin/policies/{app_id}/current` | AppOwner+ | 当前生效版 |
| POST | `/v1/admin/policies/{app_id}/publish` | Security/Admin | 追加版本；须门禁凭证 |
| GET/POST | `/v1/admin/virtual-keys` | Admin/Security | VK 创建/吊销/预算 |
| GET | `/v1/admin/audit/decisions` | Auditor+ | 按 request_id/租户查询 |
| GET | `/v1/admin/audit/chain/verify` | Auditor/Admin | 哈希链校验 |
| GET | `/v1/admin/events` | Auditor+ | Domain Event 查询 |

### 1.4 审批 HITL

| Method | Path | 说明 |
|--------|------|------|
| GET | `/v1/approvals` | 队列（pending/approved/denied） |
| GET | `/v1/approvals/{id}` | 详情 |
| POST | `/v1/approvals/{id}/decide` | `{action: approve\|deny, reason}`；approve 后 resume ToolRuntime |

### 1.5 红队 Offline

| Method | Path | 说明 |
|--------|------|------|
| POST | `/v1/redteam/runs` | 提交 run（suite: promptfoo\|garak\|pyrit） |
| GET | `/v1/redteam/runs` | 列表 |

## 3. Rate Limit / Budget

- **存储**：Redis（ADR-012）
- **键**：`rl:{tenant}:{app}:{vk_id}:{window}`、`budget:{vk_id}:{day}`
- **算法**：滑动/固定窗口计数；超限 → `alert_only`（low）或 `block`（medium+，与 fail_mode 一致）
- **来源**：VK.budget + policy_binding 配额取更严

---

## 4. Approval 流程（confirm_only）

```
L4 Authorize → effect 需 HITL
  → 写 approvals(pending) + event approval.requested
  → 返回 decision=confirm_only, approval_id
  → 审批人 POST /v1/approvals/{id}/decide
  → approve: ToolRuntime.Execute + audit
  → deny: tool.denied；不执行侧效
```

超时：`approvals` TTL（默认 24h）→ expired；critical 工具不可自动 approve。

## 5. Scanner 模式（ADR-014）

| Mode | 环境变量 | 行为 |
|------|----------|------|
| `shim` | `SAFETY_SCANNER_MODE=shim` | 规则/mock；CI 默认；无外部权重 |
| `onnx` | `=onnx` | 本地 ONNX 分类器；超时同 tier |
| `remote` | `=remote` | 调用远程 SafetyClassifier HTTP |

编排：L1 输入 →（可选模型）→ L3 输出；归约 `max_strict`：`block > confirm_only > redact > alert_only > allow`。

| tier | Scanner 超时 | 超时行为 |
|------|--------------|----------|
| low | 100ms | 非关键 → alert_only |
| medium+ | 150ms | fail_closed → block |

## 6. policy_binding Schema

```yaml
policy_binding_id: pb_customer_bot
tenant_id: t_demo
app_id: customer_bot
version: 1
reason: initial
risk_tier: medium
fail_mode: fail_closed
effect_cap: draft_only
require_dual_publish: false
tool_allowlist: [search_kb]
model_allowlist: [mock-llm]
input_scanners:
  - id: secrets
    threshold: 0.5
  - id: prompt_injection
    threshold: 0.7
  - id: anonymize
    threshold: 0.0
  - id: token_limit
    max_tokens: 4096
output_scanners:
  - id: sensitive
    threshold: 0.5
  - id: toxicity
    threshold: 0.8
retention: hash_only
```

**版本规则**：`create_initial` → v1；`append_version` → prev+1；禁止 mutate；运行时只读 `current(tenant, app)`。

## 7. Gateway 时序

```
AuthN VK → RateLimit/Budget
→ resolve binding
→ L1 scan (maybe vault)
→ if block: ledger + hash_chain + return
→ L2 (budget, system hash, model/tool bind)
→ ModelProxy（/v1/safety/chat invoke 或 /v1/chat/completions）
→ L3 scan (maybe deanonymize)
→ if tool_calls: ToolRuntime | ApprovalWorkbench
→ SafetyDecision + events + hash_chain + SIEM
→ return
```

## 8. Vault / ToolRuntime / Evaluator / 工具风险（v2.1）

- **Vault**：Anonymize → 加密写 `vault_entries` → 上游仅脱敏文本 → 可信侧 deanonymize（ADR-007）
- **ToolRuntime**（ADR-008 + **ADR-019**）固定顺序：

```
Constrain → Denylist(platform∪app) → Allowlist → effect_cap
  → ToolRiskClassifier(args) → block|confirm_only|alert_only|allow
  → Execute? → Audit(always) + SIEM
```

- **policy_binding 工具相关字段**：

```yaml
tool_allowlist: [search_kb, send_email]
tool_denylist: [shell_exec]
platform_tool_denylist: [shell_exec, transfer_money_unrestricted]
email_domain_allowlist: ["company.internal", "webank.com"]
tool_risk_rules:
  - id: email_external
    tool_id: send_email
    field: to
    type: domain_not_in_allowlist
    op_risk_tier: high
    decision: confirm_only
  - id: fetch_raw_ip
    tool_id: fetch_url
    field: url
    type: url_is_ip_or_non_https
    op_risk_tier: medium
    decision: alert_only
  - id: email_evil_tld
    tool_id: send_email
    field: to
    type: regex
    pattern: "@evil\\.com$"
    op_risk_tier: critical
    decision: block
```

- **ReleaseEvaluator**：输入策略 diff + 红队摘要 + 负例；`failed` → 禁止 publish（ADR-018）
