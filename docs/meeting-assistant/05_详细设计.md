### 0.1 API / 队列量级（估算，公式可复核）

假设：每场 Dialog 交互 8 次、Pipeline 领域事件 12 次、Tool 调用 6 次、Render 1.2 次；机器段均 8 分钟。

| 流量 | 公式 | 设计取值 |
|------|------|----------|
| Dialog 短请求高峰 | 350 会话 × (1 条/15s) ≈ 23 QPS；突发 ×4 | **100 QPS**（P95&lt;3s）；单用户限流 ≤2 QPS |
| 转写就绪入队高峰 | 300/h ≈ 0.083/s；整点毛刺 ×20 | 设计突发 **2 msg/s**（队列削峰） |
| Pipeline 领域事件 | 60 并发 × 12 事件 / 480s ≈ 1.5/s；心跳与投影开销 ×10 | 总线设计上限 **20 evt/s**（非日均） |
| ToolRuntime | 6 次/场 / 480s × 60 ≈ 0.75/s；写回簇发 ×15 | 调度能力 **15 TPS**；单生产生效 Connector ≤5 TPS |
| Render | 300/h × 1.2 ≈ 0.1/s；突发 | **2/s** |
| Knowledge 检索 | 日 1640×4 / 14h ≈ 0.13/s；高峰场×4/3600 | 常态 **~0.3 QPS**；突发 **10 QPS** |

限流：设计人口 + 部门配额双层；单部门 Pipeline 提交高峰 ≤ 全行 40%。

## 1. 逻辑模块与进程映射

| 逻辑模块 | 进程/服务 | 伸缩 |
|----------|-----------|------|
| Channel BFF | `ma-bff` | HPA by CPU/RPS；副本 ≥2 |
| Orchestrator | `ma-orchestrator` | 无状态；会话状态在 Redis/MySQL |
| Pipeline | `ma-pipeline-worker` | 并发槽位默认 **60**（可配）；队列消费者 |
| Render | `ma-render-worker` | 与 pipeline 隔离；默认突发 2/s |

**工作窗调度（与 04 一致）：**

- `09:00–23:00`：全功能；HPA 放开到设计水位；`pipeline_max_inflight=60`  
- `23:00–09:00`：允许 `pipeline.new` **入队并消费**；Agentic 多跳上限 = 日间 **30%**；禁止大规模索引重建；Dialog 以只读 + 紧急 HITL 为主

## 5. 关键时序

### 5.1 会前 Dialog + briefing

```text
User → BFF → Orchestrator.Dialog
  → Intent（scenario_hint）
  → 加载 Skill L1（仅 approved）
  → Policy 冻结 policy_binding（reason=initial）
  → Schedule（高风险 HITL）
  → ToolRuntime → Meeting API
  → Knowledge.briefing（Continuum+Docs，先 ACL）
  → 回复用户 + meeting.scheduled
  # 会后：闸门变化时追加 policy_binding 版本（ambiguity_changed / understanding_changed / pre_embed）
```

### 5.2 会后 Pipeline（playbook 默认序）

```text
transcript.ready
  → pipeline_run 创建（budget 快照，含 wall_clock）
  → understand → retrieve? → extract → artifact（Envelope）
  → schema_validate          # Hook 墙（独立步）
  → policy_hooks             # Hook 墙（独立步；含 production_effect_cap 禁令）
  → evaluate → hitl?
  → embed?（受 embed_gate；L0 跳过；work_object.production_effect ≤ cap 另判）
  → continuum.write_decided
  → 物化 acl_view[] → render / render.skipped / delivery.suppressed
  → delivery.sent | delivery.suppressed
  → pipeline.terminal
```

sop 模式：以场景 `steps.yaml` 替换中间编排；**不得跳过** validate Hook / evaluate / write_class 决策。

### 5.3 回流

```text
Connector Webhook → work_link.synced
  → 更新 work_object.status
  → 更新 Continuum open_work_links
  → 可选 Dialog 通知责任人
```

### 5.4 先 ACL 后渲染 + critical 投递（硬约束）

```text
# critical：默认可转发长文不落盘、不投递
if classification == critical and critical_delivery_default == off:
    allow = explicit_allow_list  # 须 HITL 确认的极窄集合；可空
    if allow.empty:
        create render_job(skipped, delivery_suppressed=true)
        emit render.skipped + delivery.suppressed
        return
    candidates = allow          # 只对这些人建视图；禁止扩到「ACL 过了的其他人」
else:
    candidates = normal_acl_candidates(meeting)

views = build_acl_views(meeting, candidates)
if views.empty:
    emit render.skipped + delivery.suppressed
    return

for view in views:
    filtered = project(artifacts, view.acl)
    if filtered.empty:
        emit render.skipped for view
        continue
    # 仅此时才允许持久化 render_artifact（对象存储）
    job = render_job(acl_view_id=view.id, …)
    arts = render(filtered, template) → render_artifact[]
    if policy allows deliver(view):
        deliver(arts); emit delivery.sent
    else:
        # 已渲染但禁投递：critical 下禁止走到这里（candidates 已收窄）
        emit delivery.suppressed
```

**禁止** `render(full_artifacts)` 后再按收件人删 HTML。  
**禁止** critical 在无白名单时生成任何可转发 `render_artifact`。  
**禁止** critical 白名单模式下把非白名单用户纳入 `candidates`。

## 6. 组件详细设计

### 6.1 Orchestrator

- 输入：用户消息 / 事件  
- 状态：阶段枚举 `pre_meeting | post_meeting | hitl | closed`  
- **路由**：读取 `scenario_profile.orchestration_mode` → `sop_executor` | `playbook_executor` | L0 `fallback`  
- **实现（脱敏重建版）**：`jiyaojun/app/orchestrator/service.py` + `StepEngine`（阶段式状态机，非 ReAct）  
- 只持索引与策略快照 ID，大对象落存储  
- 打断：INTERRUPT 取消 pipeline lease；IMMEDIATE 读进度；DEFERRED 改 Render 模板  

### 6.2 PolicyEngine

`embed_gate` 合并（仅三态：`block > confirm_only > allow`）：

```text
embed_gate = max_strict(
  scenario.default_embed_gate,
  classification_template_gate,   # critical → 至少 confirm_only
  ambiguity_open ? confirm_only : allow,   # 若涉 production_effect 相关歧义 → block（见下）
  understanding_blocks_decision ? block : allow,
  mode==playbook ? confirm_only : allow    # playbook 至少 confirm_only
)
# 另：production_effect_cap（policy_binding）约束 work_object.production_effect（实际请求等级）
# 实际等级不得超过 cap；production 级写回还须 L3+sop+HITL+Policy 显式放行
# 若 ambiguity_open 且候选释义影响生产生效：cap 保持 ≤draft_only，且 embed_gate=block
```

### 6.3 ToolRuntime

管道：`Validate → Authorize → Execute → Verify → Audit`  
超时、熔断、按 `connector_id` 限流（避免打满行内系统）。  
设计目标：全行 Tool 调度能力约 **15 TPS** 峰值；单个生产生效类 Connector 默认 **≤ 5 TPS**。

### 6.7 Dialog 会话与 Agent loop（Ch2/4）

- **Session journal**（`app/memory/`）：branch marker **自身为 active leaf**；fork 后新分支；JSONL **同进程 RLock**（跨进程需外锁）；forward parent fail closed；`DeterministicExtractiveSummarizer`  
- **BoundedAgentLoop**：tool → observation → 下一轮 planner；suspend 存 discovery grant；resume = allowlist ∩ grant；中文建任务/建缺陷选对 connector  
- **DialogSessionService**：BFF 传 principal；session owner/org **不可变**；chat/resume/context/task/cancel 校验 owner/admin  
- **Lazy discovery**：policy deny-first → min_score → top-k summary + grant 审计 → lazy schema（递归 sanitizer 深拷贝）  

### 6.8 调度（Ch4 async 最小实现）

- `InProcessScheduler`：**合作式 `CancellationToken`**（副作用前检查；**不可强杀线程**）  
- 任务状态写入 session journal；进程重启未终态 → `orphaned/needs_resume`  
- 终态锁内不可被后到线程覆盖；Dialog `ask`/status 不被阻塞  
- **无真实 MQ**；接口可换 Redis/队列适配器  

### 6.4 Knowledge

- Query 构造：purpose + org_domains + series/project  
- ACL 预过滤 → Hybrid → Rerank → contextual prefix →（预算内）Agentic rewrite  
- 写入：`continuum_write_class` ∈ {wide, domain, sealed, none}  
- **跨会 open items**：`MeetingSeriesStore` 与 Continuum 经 `SeriesContinuumBridge` 桥接；**Continuum 接受后才进 SeriesStore**；briefing 按 user/org/ACL/write_class 过滤；`none` 禁止索引  
- **StepEngine fail-closed**：未知 step type / validate hook / embed tool 均 `terminal=failed`，禁止静默回退 connector  
- **Usage**：`measurement_mode=simulated`；`llm_tokens_simulated` 非生产实测  
- **脱敏重建版 CI**：默认 `bge-m3-shim` + 内存索引（见 09）；不等于生产向量服务已上线  

### 6.5 RenderEngine

- 输入：`acl_view` + template_id（Skill 或 default）  
- 图表：只读 Envelope `chart_series`  
- 输出：`render_artifact`（html/mime/chart json）+ hash  
- PDF：V1 可选异步附件，失败不阻断 email_html  

### 6.6 Governance

状态机：`draft → in_review → approved → deprecated`  
`approved` 必备：`eval_run` 绿 + approver 角色匹配 classification。

### 6.7 Observability / Quota

每场 `pipeline_run` 写 spans；异步汇总 `usage_ledger`。  
耗尽：发 `budget.exhausted`，terminal 按 03 §2.11。

**默认配额（可按域调）：**

| 配额项 | 默认 / 场 | 说明 |

### 11.1 错误预算（工作窗可用性）

目标：核心 API（Dialog/HITL/查询）工作窗月可用率 **≥ 99.5%**。

| 项 | 值 |
|----|-----|
| 月工作窗时长 | 约 14h × 22 工作日 ≈ **308h** |
| 允许不可用 | \(308\times0.5\%\) ≈ **1.54h**/月 |
| 记入错误预算 | 5xx、核心读写失败、鉴权故障；**不含** LLM 慢导致的「排队变长但可完成」 |
| 耗尽动作 | 冻结非紧急发布；开启只读/降级草稿模式；优先恢复 ToolRuntime 与队列 |

### 11.2 上线门禁

矩阵内目标故事 eval 绿 + 容量测通过 + governance 流程可用 + critical 投递负例通过。
