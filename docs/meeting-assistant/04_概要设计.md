## 1. 设计目标与边界

### 1.1 目标

在权限、确认与评测约束下，将「条线 × 场景」会议转化为：

1. **结构化 Artifact**（事实真相）  
2. **工作系统嵌入**（WorkObject / work_link 回流）  
3. **多形态可读交付**（邮件 HTML / 图表 / HTML 报告，先 acl_view 再渲染）  
4. **跨会 Continuum**（接着上次开）

### 1.2 非目标（V1）

会中全双工语音、RL 后训练、自动造工具、自由拖拽排版器、一次覆盖全部 39 故事深嵌入（先按 03 §2.18 矩阵）。

### 1.3 成功标准（产品）

- 优先故事矩阵内场景可演示：理解 → 产物 →（确认后）嵌入 → 回流 → 按权限渲染投递  
- 管理会成功看台账/看板，不看邮件是否漂亮  
- critical 场景不入宽 Continuum、默认可转发长文不落盘

## 2. 容量与业务负荷模型

### 2.1 给定参数

| 参数 | 值 | 说明 |
|------|-----|------|
| 行内使用人数 | **8,000** | 注册/可授权用户规模 |
| Buffer | **+30%** | 增长、峰值毛刺、演练冗余 |
| **设计容量人口** | **10,400** | \(8000 \times 1.3\) |
| 主要工作时段 | **09:00–23:00** | 共 **14 小时**/日；夜间仅保留异步收尾与低优先级任务 |

### 2.2 负荷假设（可调；变更走容量评审）

**Buffer 只用一次，避免叠乘：**

- **并发/账号水位**用设计人口 \(8000\times1.3=10400\)  
- **日流量**用注册用户 8000 估算后再 ×1.3  

| 假设项 | 取值 | 推导 |
|--------|------|------|
| 日活占**注册**用户 | 45% | DAU = \(8000\times0.45=3600\) |
| 日均经纪要君处理场次 | 0.35 场 / DAU | 业务日量 \(3600\times0.35=1260\)；**×1.3 buffer** → 设计日处理 **≈1,640** 场（精确 1638） |
| 高峰小时占比 | 日设计量的 **18%** | 高峰 ≈ **295** 场/小时；设计取 **300**/h（10–11、16–18、21–22） |
| Pipeline 机器段墙钟 | 平均 **8** 分钟 | 不含 HITL 人工等待 |
| Dialog 同时在线 | 设计人口 × **2.5%** | \(10400\times0.025=260\)；设计取 **350**（含毛刺） |
| Pipeline 机器段并发 | 高峰×8/60 | \(300\times8/60=40\)；设计取 **60**（含毛刺 ≈+50%） |
| HITL 挂起槽位 | 高峰×30% | \(300\times0.3=90\)；设计取 **120**（+30% 毛刺） |

### 2.3 容量目标（SLO 输入）

| 能力面 | 设计目标 |
|--------|----------|
| 账号/授权主体 | ≥ **10,400** |
| Dialog 峰值并发会话 | ≥ **350** |
| Pipeline 机器段峰值并发 | ≥ **60** |
| 日处理会议 | ≥ **1,640** |
| Dialog 短请求高峰 | ≥ **100 QPS**（见 05 公式） |
| 高峰建会/写回 API | 见 05 TPS 表 |
| **夜间策略（09 外）** | **23:00–09:00**：允许 `pipeline.new` **入队**并继续消费；Agentic 多跳上限降为日间 **30%**；**禁止**大规模索引重建；Dialog 只读+紧急 HITL |

> 说明：夜间仍收转写就绪，避免早高峰积压爆炸；与「禁新增大规模 Agentic」一致的是**降预算**，不是拒收队列。

### 2.4 弹性原则

- **水平扩展优先**：Pipeline Worker、Render Worker、Retriever 无状态可扩容  
- **队列削峰**：转写就绪 → 入队，避免整点会议结束打爆 LLM  
- **配额护栏**：按 OrgDomain/Scenario 的 CostQuota（架构 §2.15），防单部门打满全行额度  
- **分级降级**：LLM 抖动时优先保证 HITL 安全与「只出草稿」；漂亮渲染可延后

## 3. 系统上下文

```text
                 ┌──────────── 企微 / 内网 Portal / OpenAPI ────────────┐
                 └─────────────────────┬────────────────────────────────┘
                                       │ AuthZ（行内统一身份）
                 ┌─────────────────────▼────────────────────────────────┐
                 │              纪要君 Meeting Assistant                  │
                 │  Orchestrator · Dialog · Pipeline · Render · Policy   │
                 └─┬───────────┬───────────┬─────────────┬──────────────┘
                   │           │           │             │
         会议/日历/通讯录    ASR/转写     行内文档库    工作系统 Connectors
         (Meeting APIs)   Adapter      Knowledge     (执行系+管理系 / MCP)
```

外部依赖均为 **Adapter + SPI**；Agent 不直连外部 HTTP。

## 4. 逻辑架构（与 v7.7 对齐）

```text
Channel / AuthZ
  → MeetingOrchestrator
       ├ Dialog Plane          # 预订、澄清、HITL、问进度
       ├ Pipeline Plane        # 理解→产物→评估→嵌入→索引
       ├ Presentation/Render   # 先 acl_view 再邮件/图表/HTML
       └ PolicyEngine          # embed_gate / ACL / write_class / delivery
  → ToolRuntime（唯一副作用出口）
  → Domain Events Bus
  → Stores：MySQL · Redis · ES(+向量) · 对象存储
  → Observability：trace / usage_ledger / quota
  → Governance：Skill/词表/模板审批
```

模块职责摘要：

| 模块 | 职责 |
|------|------|
| Orchestrator | 阶段控制、Skill 选择、平面调度、停止条件 |
| Dialog | 低延迟交互；不跑长 Map-Reduce |
| Pipeline | 按 playbook 或 sop/steps.yaml 编排 |
| Understanding | 转写质量、分域词表、未知术语 |
| Artifact | 产出带 **ArtifactEnvelope** 的结构化产物 |
| Evaluator | 新鲜上下文验收；失败不得 embed |
| WorkEmbed | Connector 写回；幂等；回流 |
| Knowledge | Docs + Continuum；Hybrid RAG；write_class |
| Render / Delivery | acl_view → 模板渲染 → 投递 |
| Policy / Governance / Eval | 闸门、审批上线、故事评测门禁 |

## 5. 部署架构（概要）

### 5.1 运行时拓扑

| 组件 | 形态 | 说明 |
|------|------|------|
| `api-gateway` / BFF | 无状态多实例 | 企微回调、Portal、OpenAPI |
| `orchestrator-service` | 无状态多实例 | 会话编排、事件消费入口 |
| `pipeline-worker` | 可扩容消费者 | 会后长任务；并发按 §2.3 |
| `render-worker` | 可扩容消费者 | CPU/IO 型；与 Pipeline 隔离扩容 |
| `toolruntime-service` | 带熔断的副作用执行 | 限流、幂等、审计 |
| MySQL | 主从 | 事务真相 |
| Redis | 集群 | 会话热数据、限流、锁、幂等 TTL |
| Elasticsearch | 集群 | 通讯录、sparse、可选 dense |
| 对象存储 | 行内标准 | 转写原文、渲染大对象、密封原文 |
| 消息队列 | 行内标准（Kafka/RocketMQ 等） | domain_event 与任务队列 |

### 5.2 环境

`dev` / `sit` / `uat` / `prod`；生产禁止加载 `governance.status!=approved` 的 Skill。

### 5.3 高可用与容灾（概要）

- 无状态服务多 AZ；队列与 DB 按行内规范  
- Pipeline 任务可重试且幂等（idempotency_key）  
- critical 数据默认不进宽检索集合；备份按 retention_class

## 6. 技术选型原则

| 领域 | 原则 | V1 倾向 |
|------|------|---------|
| 编排 | 有状态图 + HITL + checkpoint | 可兼容 LangGraph 类；**契约以 03 为准** |
| 服务语言 | 与行内主力栈一致 | 详细设计给接口，不绑死语言 |
| LLM | 行内网关；分场景模型档位 | 高风险叠加独立 Evaluator 模型/上下文 |
| 检索 | Hybrid + Rerank + 先 ACL | ES + vector_ref 原则（03 §2.19） |
| 连接器 | MCP 可接入 + 原生适配可并存 | 禁止仅私接无协议 |

## 7. 安全与合规（概要）

- 统一身份注入 `user_id`；模型不可覆盖 AuthZ  
- `classification` + `continuum_write_class` + `delivery_scope`  
- 日志脱敏；critical 强脱敏  
- ToolRuntime 审计全量；生产生效类默认 block  
- 转写/外部材料为不可信通道，不得直接变工具参数  

---

## 8. 质量属性

| 属性 | 概要指标 |
|------|----------|
| 可用性 | 工作窗 09:00–23:00 核心 API ≥ **99.5%**/月；错误预算见 **05 §11.1** |
| 对话延迟 | 普通澄清 P95 &lt; 3s（不含用户思考）；预订 HITL 以人工为准 |
| 会后产出 | 机器段（无 HITL 等待）P95 &lt; 10min / 场（≤60 分钟会）；超长会分片 |
| 正确性 | 故事评测门禁；上线 Skill 必须 approved + eval 绿 |
| 成本 | 场均 token/工具调用受 CostQuota；超限 terminal=budget |

## 10. 风险（概要）

| 风险 | 对策 |
|------|------|
| LLM/ASR 抖动 | 队列、配额、降级只出草稿 |
| 整点会议潮汐 | Worker 弹性 + 入队削峰 |
| 跨系统权限不一致 | Policy 快照 + 写回前二次 AuthZ |
| 场景配置腐化 | Governance + Eval 门禁 |
| 容量假设偏差 | 试点 2 周校准校准，再调 Worker / 配额 |
