## المفهوم الأساسي: الوكيل = نموذج لغوي كبير + السياق + الأدوات

الصيغة الأساسية لهذا الكتاب هي **الوكيل = نموذج لغوي كبير (LLM) + السياق + الأدوات**. يشرح الفصل الأول الوكيل نفسه على ثلاثة مستويات: مستوى التنفيذ هو هذه الصيغة، والمستوى الحدسي هو «العقل + العينان + اليدان والقدمان»، أما المستوى الأكاديمي فيقابل السياسة (Policy) وفضاء الملاحظة (Observation Space) وفضاء الفعل (Action Space).

| المكوّن | التشبيه | الدور |
| :--: | :--: | --- |
| 🧠 **النموذج اللغوي الكبير** | العقل | يوفر قدرات الفهم والاستدلال واتخاذ القرار |
| 👁️ **السياق** | العينان | كل ما يستطيع الوكيل رؤيته عند كل نقطة قرار: موجّه النظام، وتعريفات الأدوات، ورسائل المستخدم، وردود النموذج، ونتائج تنفيذ الأدوات |
| 🤲 **الأدوات** | اليدان والقدمان | إدراك البيئة وتنفيذ الأفعال والتفاعل مع العالم الخارجي |

في بيئة الإنتاج يعيد الفصل الأول كتابة النظام نفسه بالصيغة **الوكيل = Model + Harness**، حيث **Harness = إدارة السياق + واجهات الأدوات + القيود + التحقق + التصحيح**. وهذه البنود الثلاثة الأخيرة هي بالضبط الفجوة بين عرض توضيحي يعمل ومنتج موثوق.

## مسار التعلم

تحدد «المقدمة» البنية العامة على النحو التالي: **تبني الفصول 1–6 منهجًا متكاملًا لبناء الوكيل، بينما تناقش الفصول 7–10 تحسين القدرات من أربعة اتجاهات: التقييم، وما بعد التدريب، والتطور المستمر، والتعاون متعدد الوكلاء.** ويرافق كل فصل فكرة أساسية:

| الجزء | الفصل | ما يغطيه | الفكرة الأساسية |
| --- | :--: | --- | --- |
| **البناء** | 1 | العناصر الثلاثة، وحلقة ReAct، وأنماط التنسيق (سير العمل مقابل الاستقلالية)، وهندسة Harness | الفجوة بين عرض توضيحي يعمل ومنتج موثوق تكمن في Harness لا في النموذج |
| | 2 | بنية رسائل واجهة البرمجة، وذاكرة KV المخبأة، وهندسة الموجّهات والدفاع ضد حقن الموجّهات، وAgent Skills، وشريط حالة الوكيل، وضغط السياق | أهم فصل في الكتاب؛ السياق يحدد سقف القدرات، وكلما كانت البادئة أكثر ثباتًا ارتفعت نسبة إصابة المخبأ |
| | 3 | أربع استراتيجيات تدريجية لذاكرة المستخدم، وحزمة RAG، وتنظيم المعرفة واسترجاعها، وRAG القائم على الوكلاء، والذاكرة متعددة الوسائط | يوسّع السياق من جلسة واحدة إلى معرفة تتراكم عبر الجلسات |
| | 4 | خمس فئات من الأدوات (الإدراك / التنفيذ / التعاون / تشغيل الأحداث / التواصل مع المستخدم)، وMCP، ومبادئ التصميم العامة، والاكتشاف النشط للأدوات | أدوات الإدراك تضبط حجم المعلومات، وأدوات التنفيذ تضبط المخاطر؛ وينبغي تصميم الأدوات لتكون عامة |
| | 5 | وكيل البرمجة مع نظام الملفات، ومعمارية OpenClaw، وستة اتجاهات للكود بوصفه قدرة فوقية | الكود ليس مجرد كتابة برامج، بل قدرة فوقية تُنشئ أدوات جديدة أثناء التشغيل |
| | 6 | محوران، الوسائط × التوقيت: العمل غير المتزامن والمدفوع بالأحداث، والصوت، وComputer Use، وتشغيل الروبوتات | تتشارك أنواع التفاعل الأربعة البدائيات النظامية نفسها: الإيقاظ، ونقاط الأمان، والإلغاء، والاستباق، وفصل المسارين السريع والبطيء |
| **التحسين** | 7 | بيئات التقييم، ومنظومة المقاييس، وتصميم مجموعات البيانات، وLLM-as-a-Judge، والدلالة الإحصائية، وقابلية الملاحظة، وبيئات المحاكاة | من دون تقييم لا يمكن تمييز «التحسن الناتج عن التصميم» من «التذبذب العشوائي» |
| | 8 | بانوراما المراحل الأربع، وMid-training/SFT/RL، وتصميم المكافآت، وإسناد الفضل عبر جولات متعددة، والتقطير | يحفظ SFT ويعمّم RL؛ والبيانات والبيئات أهم من الخوارزميات |
| | 9 | إشارات التعلم (نتائج البيئة / قواعد العملية / LLM Rubric)، وأربعة حوامل للتحديث — المعرفة والتعليمات والبرامج والمعلمات — إضافة إلى الإطلاق التدريجي والتراجع | يعتمد حامل التحديث على كيفية التعبير عن القدرة والتحقق منها |
| | 10 | إطار التصنيف (سياق مشترك أو منفصل × ندّي / مدير / لامركزي)، وبروتوكول A2A، وستة أنماط للفشل، ومجتمع الوكلاء | لكل قرار تصميم في نظام متعدد الوكلاء نظير ضمن العناصر الثلاثة للوكيل الواحد |

## تقسيم العمل بين النص والتجارب

الكتاب ليس برنامجًا تعليميًا خطوة بخطوة لـ SDK واحد. يجيب pseudocode والهياكل القصيرة في النص عن «كيف تتدفق الحالة، وأين يمكن التوقف، وأي نوع من الإشارات يشارك في التحقق» فحسب؛ أما تجارب الفصول فتقدم التنفيذ الكامل ومحولات النموذج والبيئة والاختبارات والسجلات والأدلة. ولست بحاجة عند قراءة تجربة إلى فهم كل سطر في كل ملف، ولا ينبغي اعتبار طريقة استدعاء واجهة برمجة محددة في تجربة واحدة معمارية عامة.

يُنصح بالقراءة على الطبقات الثلاث التالية؛ وفي الفصول المعقدة اختر عدة تجارب آليات من الطبقة نفسها بدلًا من تشغيل مشروع واحد فقط:

| الطبقة | اقرأ أولًا | تخطَّ مؤقتًا | السؤال الذي تجيب عنه |
| :--: | --- | --- | --- |
| **Starter** | README المشروع: الهدف، والأمر الأدنى، وشروط القبول؛ وskeleton المقابل في النص | بيانات الاعتماد وواجهة المستخدم ومحوّلات المزوّدين والسجلات الخام الطويلة | ما الآلية التي يُفترض أن تثبتها التجربة؟ |
| **Builder** | نقطة الدخول والحلقة الأساسية ومخطط الحالة/الرسائل والأدوات وأداة التحقق | طبقات التوافق والنشر غير المرتبطة بالآلية | أي متغير غيّر السلوك؟ |
| **Maintainer** | الاختبارات ومعالجة الأعطال وتنسيق الأدلة وmanifest/hash ومسار التراجع | تفاصيل الأطراف الثالثة اللازمة فقط عند تعديل التجربة | هل يمكن إعادة إنتاج النتيجة وهل سُجلت الأعطال بصدق؟ |

يحدد README كل فصل نقطة الدخول Starter الخاصة به. والمجموعة الأولى الموصى بها هي: الفصل 1 `context`، والفصل 2 `context-compression`، والفصل 3 `user-memory`، والفصل 4 `execution-tools`، والفصل 5 `coding-agent`، والفصل 6 `live-audio`، والفصل 7 `tau2-bench-eval`، والفصل 8 `cot-distillation`، والفصل 9 `trajectory-verifier`، والفصل 10 `parallel-web-research`. ويحدد Code map في كل مجلد أقسام Run first وCore behavior وVerifier، والأجزاء التي يمكن تخطيها في القراءة الأولى.
