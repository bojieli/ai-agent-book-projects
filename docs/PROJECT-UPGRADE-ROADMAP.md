# 两个项目 12 周升级路线

> 状态：等待最终共识确认，不代表已经开始实施。  
> 项目定位：生产架构脱敏重建。  
> 目标：求职展示 + 可供企业二次接入。  
> 资源：单人、8～12 周、无真实企业环境。

## 当前程度

### 纪要君

当前属于较强的工程化 PoC，已经完成领域边界、Skill Pack、Bounded Agent Loop、Session Journal、Continuum、ACL-first RAG、SOP/Playbook、HITL、ToolRuntime 和自动化门禁。

距离可信的本地企业级实现，主要缺少真实持久化、真实向量检索、商业模型调用、可恢复任务调度、完整观测和一条端到端业务闭环。

### AI 安全控制面

当前属于较强的工程化 PoC，已经完成 L1–L4、五态 SafetyDecision、规则与 Judge 插槽、Dual-Gate、策略审批、审计链和部署骨架。

距离可信的本地企业级实现，主要缺少商业 Judge 实测、数据出站治理、多副本审计一致性、身份/密钥/观测联调、线上反馈替代机制和性能证据。

## 投入原则

- 纪要君投入约 70%，安全控制面投入约 30%。
- 纪要君是旗舰业务项目，安全控制面作为可复用治理平台单向被调用。
- 12 周内冻结新 Skill Pack、新 Scanner 和控制台 UI。
- 不继续扩大 Mock 广度，不在小型 shim 黄金集上刷分。
- 每项能力必须同时提供正常路径、失败路径和可观测证据。

## 目标架构

### 本地基础设施

- Core：PostgreSQL、Redis、SeaweedFS（S3）、Qdrant。
- Worker：Celery + Redis。
- Identity：Keycloak。
- Secrets：OpenBao 开发模式。
- Observability：OpenTelemetry、Prometheus、Grafana、Tempo。
- 外部工作系统：Jira/企微确定性契约模拟器，只实现创建、幂等、失败、超时、回调和状态变化。

所有组件使用分层 Docker Compose profile；默认启动 Core，完整演示再启动身份、密钥和观测组件。Compose 跑稳后才使用 kind 验证 Helm。

### 模型与安全

- 模型通过 OpenAI-compatible 商业 API 接入，不绑定厂商。
- 纪要君不得绕过安全控制面直连模型。
- 确定性规则先行，商业 Judge 只处理灰区和远程评测。
- 只有脱敏后的 public/internal 内容允许出站。
- confidential/critical、密封内容、凭据和真实身份禁止出站。
- 单请求限制输入 8K、输出 2K token；每日最多 100 次；默认月预算 200 元。
- 自动化测试默认使用确定性替身；远程模型评测显式 opt-in。

### 双重授权

- 纪要君判断用户是否拥有业务权限。
- 安全控制面施加不可放宽的内容和操作风险上限。
- 最终处置取两者中更严格的结果。
- 模型调用走 OpenAI-compatible 安全代理。
- 工具执行前调用独立安全授权接口。
- trace_id、org_domain、policy_binding 贯穿双方审计。

## 旗舰故事

唯一主路径采用：

> 技术评审 → 识别问题 → 形成结构化会议产物 → 人工确认 → 创建缺陷 → 接收状态回调 → 下次会议从 Continuum 继续跟踪。

辅助失败与安全场景：

- 发布检查不通过时阻断写回。
- 高敏会议内容密封，禁止越权检索和外部模型出站。
- 商业模型超时或预算耗尽时，只读草稿可降级，高风险流程必须关闭失败。

## 分阶段路线

### 第 1～2 周：基础环境与边界

- 建立分层 Docker Compose。
- 完成 PostgreSQL、Redis、SeaweedFS、Qdrant 的健康检查和迁移。
- 固化模型代理、工具授权、数据出站和预算契约。
- 建立统一配置、密钥占位和离线默认模式。

阶段门：一条命令启动 Core；无商业 API Key 时全部离线门禁仍可运行。

### 第 3～5 周：真实数据面与模型链路

- 纪要君核心状态从 JSON/内存迁移到 PostgreSQL。
- Session、任务投影和幂等状态进入持久化存储。
- RAG 使用真实 Qdrant 与真实 Embedding。
- 长任务迁移到 Celery Worker，验证重启恢复。
- 商业模型调用统一经过安全代理，落实分类、脱敏、超时和预算。

阶段门：关闭任一核心组件时能够给出明确失败或安全降级，不产生重复副作用。

### 第 6～8 周：R1 真实闭环

- 跑通技术评审主路径。
- 实现 Jira/企微确定性模拟器和 webhook 状态回流。
- 将工单状态写回 Continuum，并在下一场会议 briefing 中召回。
- 补齐业务权限与安全风险双重判定。
- 实现模型超时、安全阻断和重复 webhook 场景。

阶段门：主路径可重复演示，重复执行不会重复建单，失败后可恢复。

### 第 9～10 周：安全与可观测

- 接入 Keycloak 与 OpenBao profile。
- 接入 OpenTelemetry、Prometheus、Grafana、Tempo。
- 完成商业 Judge 灰区路径和远程对比报告。
- 完成审计链并发写策略，至少验证双副本不会产生未检测分叉。
- 自动执行强制故障矩阵。

阶段门：每次模型调用、检索、HITL、工具授权和写回均可从 trace 追踪。

### 第 11～12 周：评测、性能与演示

- RAG 黄金集扩到 60 条。
- Agent 主路径和失败故事扩到 30 条。
- ACL、密封数据、跨域越权负例不少于 20 条。
- 安全平台保留 2400+410 静态门禁，不继续为离线分数扩规则。
- 商业 Judge 每周 opt-in 比较 100 条，发布前人工触发 300 条。
- 完成性能报告、故障报告、操作手册和一键演示。
- Compose 验收通过后，再用 kind 验证 Helm。

## 最终验收

- 安全规则路径 P99 不超过 80ms。
- RAG 本地检索 P95 不超过 500ms。
- 外部模型调用超时为 5 秒，提供方耗时单独统计。
- 会后流水线 P95 不超过 2 分钟。
- 重复创建任务或缺陷数量为 0。
- Worker 重启后任务能够恢复，不重复产生副作用。
- 商业模型超时、Qdrant 暂停、Redis/Worker 重启、重复 webhook、PostgreSQL 短暂不可用、安全阻断和预算耗尽均有自动化证据。
- 默认离线测试不依赖网络、商业模型可用性或付费额度。
