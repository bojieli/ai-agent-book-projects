## 项目经历

**项目一：数据安全监测中心** (2022.04 – 至今 | 核心开发)

**项目背景：**
面对全行海量的 WAF 日志（日均 23 亿+）、管理台操作数据（日均 10 亿+）及 RocketMQ 调用数据（日均 600 万+），传统审计模式存在滞后性。我主导研发了这套实时数据安全监测中心，覆盖敏感信息外传审计、管理台异常行为审计、薪资等特敏信息管控三类核心场景。针对 WAF 日志与管理台操作日志的异构特点，分别设计了对应的采集方案，通过引入全链路异步架构，在不增加硬件资源的前提下实现了海量数据的实时采集与审计。

**核心工作：**
*   设计多源数据采集层：WAF 日志（总盘日均 23亿+）经 Nginx 旁路采集并由风险策略抽样过滤后，实时上报至自研 Netty 服务完成实时审计与告警，其余全量写入 Hive 与 ES；管理台操作数据基于 SkyWalking 探针无侵入采集，同样落存 Hive 与 ES，兼顾离线分析与实时检索。
*   基于 Netty 自研高性能数据接收服务，单机稳定支撑万级 QPS（压测口径：接收+长度约束+CRC 校验，业务处理异步化）。采用 Reactor 主从多线程模型与零拷贝，配套私有协议解决 TCP 粘包/拆包，保证链路稳定与数据完整。
*   针对敏感信息外传、管理台异常行为、薪资等特敏信息三类场景，基于可配置规则引擎构建实时审计链路，实现字段级敏感信息识别与违规告警落地。
*   打通安全运营处置闭环：告警命中后沉淀关键上下文与证据链，支持运营侧确认/处置/留痕，并将处置结果回流用于规则优化与误报治理。
*   通过分析 Heap Dump 定位并修复了高并发下 ByteBuf 堆外内存泄露导致的 OOM 隐患；结合业务调整了 Netty 内存池分配策略，保障系统在海量数据压力下保持 99.99% 的可用性（按核心服务可用时长统计）。
*   结果：上线后持续拦截多起违规数据外传事件及管理台内部数据泄露风险，平台在资源不扩容的前提下承载数据量翻倍，线上稳定运行无重大故障。

**项目二：业务安全平台3.0** (2024.03 – 至今 | 核心开发)

**项目背景：**
面向微众银行 App 登录/转账等核心链路的高频安全威胁（盗刷、黑产、诈骗转账等），平台需要在“交易/登录前”给出同步风控决策。存量链路可用，但在时序特征与链式行为识别上能力不足，且新策略上线缺少影子验证与审计明细。我在不影响存量同步链路的前提下，做了**增量式重构**：引入 Flink 做实时特征预计算，特征按用途分别落 Redis 与 HBase，在线 API 取数后执行规则并返回动作。

**核心工作：**
*   增量式重构：保留存量同步决策入口不动，新增 RocketMQ 事件流 + Flink 预计算链路；将时序特征前置计算，按用途分别落 Redis 与 HBase，在线侧以“取特征 + 规则计算”为主，减少同步链路对下游服务调用的依赖。
*   时序指标治理：统一事件时间与水位线策略，避免窗口类指标受乱序/延迟影响；通过 Checkpoint 保证状态一致性与恢复正确性。
*   策略配置化：规则表达式入库（Aviator），配置变更通过 MySQL CDC 下发；支持快速调整与回滚，减少策略迭代对发版的依赖。
*   链式欺诈识别：基于 Flink CEP 建模多步行为序列（例如“新设备/异地登录 → 改密 → 小额试探 → 大额转出”），设置时间窗口与中间状态约束，命中后输出命中路径与关键上下文（设备/IP/金额等）用于处置与复盘。
*   影子验证（Shadow Mode）：新策略默认只产出命中明细落 ClickHouse（不影响主链路决策），按命中率/误拦样本等口径评估效果；达标后再切换为生效策略，并保留明细用于审计追溯。
*   结果：对外同步决策接口 P99 < 150ms、日均调用量 1000 万+（监控口径）；新策略上线前可基于真实流量验证，降低误拦风险；决策明细可审计、可追溯。

**项目三：企业智能会议 Agent 平台（纪要君）** (2025.06 – 至今 | 核心开发)

**项目背景：**
行内智能会议助理平台，覆盖会前预订与会后纪要。重点在工程可控与稳定：工具调用链路可靠、关键操作可人工确认、会话状态可追溯。

**核心工作：**
*   基于 LangGraph 构建“意图识别 → 置信度阈值路由 → 专项处理”的多 Agent 调度链路；意图分类采用纯 LLM 实现，为不同意图配置独立阈值，低置信度自动降级到通用处理，降低误路由触发高风险操作的概率。
*   在会议 Agent（HITL 版本）接入会话状态持久化（SQLite/MySQL/内存多模式），支持跨会话恢复执行，提升长链路任务的稳定性与可追溯性。
*   建设会前高风险操作的 Human-in-the-loop 确认与前置参数校验中间件，将创建/修改/取消等动作纳入结构化确认流程；支持用户在确认阶段用自然语言修订参数并触发重新规划。
*   实现会后纪要自动生成与发送：对接腾讯会议纪要/转写文本获取，结合智能分片与合并总结生成结构化纪要与行动项；支持 Markdown/HTML/邮件模板化输出，并实现会后自动发送纪要的异步任务。
*   针对“声称成功但未实际调用工具”的幻觉问题，构建规则优先、必要时 LLM 语义兜底的检测机制，并在命中时从上下文自动提取参数补执行工具，减少静默漏执行。
*   封装模型消息序列修复与长对话安全截断逻辑，确保“工具调用-工具结果”配对完整，降低因上下文截断或序列不合法导致的 API 报错与链路抖动。
*   结果：创建/修改/取消等高风险操作可控且可审计；会后纪要可自动生成并按模板输出/发送；复杂场景下工具链路更稳定，模型调用成本明显下降。
