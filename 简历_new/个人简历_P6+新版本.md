## 项目经历

**项目一：数据安全监测中心** (2022.04 – 至今 | 核心开发)

**项目背景：**  
面向全行海量安全日志场景，传统审计方式存在发现滞后、处置链路割裂与资源成本高的问题。我负责该平台核心链路建设，围绕高吞吐采集、实时审计、告警处置与线上稳定运行几个目标推进方案落地，在资源基本不扩容的前提下支撑数据规模持续增长与能力演进，并通过“高危必采、中低危按策略抽样、全量离线兜底”的分层策略，在实时性、成本与稳定性之间做取舍。

**核心工作：**
* 负责多源日志实时采集链路设计与落地，针对 WAF 旁路日志、管理台操作探针数据与 RocketMQ 调用日志设计差异化接入方案，兼顾高吞吐实时审计与离线补偿能力。
* 负责高吞吐接收服务与协议设计，基于 Netty 构建异步接收链路，解决高并发场景下的吞吐、粘拆包、带宽与数据完整性问题，单机稳定支撑万级 QPS。
* 推动审计能力从“规则命中”向“告警处置与回流优化”延伸，沉淀告警上下文、证据链与运营回流机制，提升后续误报治理与规则优化效率。
* 处理并定位高并发下 ByteBuf 堆外内存问题，结合有界队列、降级策略与内存池参数调整完成止血和治理，支撑系统在海量数据压力下稳定运行。
* 结果：平台持续承载日均 33 亿+ 多源日志，在资源基本不扩容的前提下支撑数据规模增长；持续拦截多起违规数据外传事件及异常行为风险，核心服务可用性达 99.99%，系统整体保持稳定运行。

**项目二：业务安全平台 3.0** (2024.03 – 至今 | 核心开发)

**项目背景：**  
面向微众银行 App 登录、转账等核心链路的实时风控场景，平台需要在接口返回前同步给出放行、拦截、挑战动作。存量同步链路能够支撑基础规则，但随着时序特征、链式识别需求提升，以及策略验证和决策明细追溯的机制化建设要求增强，原链路在演进效率与可解释性上逐渐暴露短板。我负责推动该链路在不影响存量服务的前提下进行增量式演进。

**核心工作：**
* 推动在线风控链路由“同步现算”向“流式预计算 + 在线取特征”演进，引入 RocketMQ + Flink + Redis 的预计算链路，降低同步决策接口对下游扇出依赖。
* 负责时序指标治理，统一事件时间、水位线、Checkpoint 与状态管理口径，提升窗口类特征在乱序和延迟场景下的正确性与恢复稳定性。
* 建设策略配置化与发布验证机制，将规则表达式、规则版本控制、CDC 下发与 Shadow Mode 串成完整闭环，支持灰度放量与快速回滚，降低新策略直接上线带来的误拦风险。
* 建设命中明细与路径留痕能力，基于 ClickHouse 沉淀关键特征快照、命中路径与规则版本，提升风险处置与事后复盘的可解释性。
* 基于 Flink CEP 建设链式欺诈识别能力，支持多步行为序列识别，并输出设备、IP、金额等关键上下文，增强复杂风险场景下的识别能力。
* 结果：同步决策接口 P99 < 150ms、日均调用量 1000 万+；新策略上线前可基于真实流量完成验证，命中路径与决策明细可用于追溯复盘。

**项目三：企业智能会议 Agent 平台（纪要君）** (2025.06 – 至今 | 核心开发)

**项目背景：**  
面向行内会议场景，平台需要同时满足自动化、可靠性与合规可控要求，不仅要完成会前预订和会后纪要生成，还要支持代办事件抽取、分发与闭环跟踪。我主要负责将 Agent 历经多轮迭代从“功能可用”推进到“稳定可用”，重点解决高风险操作误触发、工具调用不稳定、会话状态不可恢复与长对话成本过高等问题。

**核心工作：**
* 负责多 Agent 路由链路设计，基于 LangGraph 构建“意图识别 → 阈值路由 → 专项处理”的调度机制，并通过风险分级阈值控制误触发概率。
* 推动高风险操作的可控化治理，建设 HITL、参数校验与确认阶段自然语言修订能力，保障创建、修改、取消等动作可审计、可确认。
* 建设会后纪要与代办闭环能力，从会议内容中抽取行动项、责任人和时间信息，支持结构化生成代办事件，并通过异步任务分发、失败重试与状态跟踪减少“纪要生成后无人跟进”的断点。
* 负责会话状态持久化与 checkpoint 粒度恢复，以及工具调用幂等与消息序列健壮性治理，结合工具调用记录提升长链路任务在异常场景下的恢复能力与调用稳定性。
* 针对工具幻觉和静默漏执行问题，建设规则优先、LLM 兜底的检测与补执行机制，减少无感失败与重复操作。
* 结果：高风险操作实现全链路可控与可审计；纪要生成、代办分发与会后跟进形成业务闭环；结合模型分层路由与长文本分片，高成本模型调用次数更可控。
