## 项目经历

**项目一：数据安全监测中心** (2022.04 – 至今 | 核心开发)

**背景：**  
全行每天产生 WAF 约 23 亿、管理台操作约 10 亿、消息调用约 600 万条安全日志。原有事后审计发现慢、处置链路长，需要在资源基本不扩容的前提下提升实时风险发现能力。

**核心工作：**
*   设计“高危必采、中低危按策略抽样、全量离线兜底”的分层链路；针对 WAF 旁路日志、管理台探针数据和 RocketMQ 调用日志采用差异化接入方案。
*   基于 Netty 自研异步接收服务，单机稳定支撑万级 QPS（接收、长度约束与 CRC 校验口径），解决 TCP 粘拆包、带宽和数据完整性问题。
*   建设字段级敏感信息识别、实时规则判断和告警证据链，并将运营处置结果回流规则侧，形成误报治理闭环。
*   通过 Heap Dump 定位 ByteBuf 堆外内存泄露，调整内存池和队列策略，消除高并发 OOM 隐患。

**结果：** 资源基本不扩容情况下支撑数据规模增长，持续发现违规外传和内部异常操作风险；核心服务可用性达到 99.99%。

**项目二：业务安全平台 3.0** (2024.03 – 至今 | 核心开发)

**背景：**  
App 登录、转账需要在接口返回前同步给出放行、拦截或挑战结论。存量链路能够支撑基础规则，但时序特征、链式行为识别和策略上线验证能力不足。

**核心工作：**
*   保留存量同步入口，新增 RocketMQ + Flink 特征预计算链路；在线侧收敛为“取特征 + 规则计算”，减少同步扇出和尾延迟。
*   统一事件时间、水位线、Checkpoint 和状态恢复口径，保证乱序、延迟和任务恢复场景下窗口指标可解释。
*   将规则表达式、版本、MySQL CDC 下发、灰度和回滚串成闭环；新策略默认 Shadow 运行，只记录 ClickHouse 明细，不影响真实决策。
*   基于 Flink CEP 识别“新设备登录 → 改密 → 小额试探 → 大额转出”等多步行为，并保留命中路径和关键上下文。

**结果：** 同步决策 P99 &lt; 150ms，日均调用 1000 万+；新策略能先用真实流量验证，决策过程可查、可复盘。

**项目三：会议 Agent 平台「纪要君」** (2025.06 – 至今 | 技术负责人)

**背景：**  
行内已有会议预订与纪要能力，但会后建单、行动项跟踪和跨会衔接仍依赖人工；同时，金融场景要求模型不能绕过权限和确认直接修改工作系统。我主导将产品从“生成纪要”升级为“受控的会议工作单元”。

**核心工作：**
*   **重定义平台边界：** 将成功标准从“产出一篇纪要”改为“形成结构化产物，并在权限、验收和人工确认通过后写回缺陷/任务系统”；未知场景只降级出草稿，不虚构 SOP、不自动触发高风险动作。
*   **拆分两类运行时：** 会前对话采用有界 Agent Loop（上下文 → 工具发现 → 决策 → 权限 Hook → 执行 → 观察回流），支持暂停、人工确认和恢复；会后长任务采用 Skill Pack 驱动的 SOP / Playbook 状态机，避免模型跳过确定性流程墙。
*   **建设分层记忆：** 追加式 Session Journal 保存会话轨迹、分支和压缩摘要；Continuum 管理跨会未关闭事项与工单回链；Glossary 管理条线术语。恢复时重新计算权限，任务和会话均做对象级授权。
*   **落地企业 RAG：** 制度按章节、转写按说话人轮次分块；先按用户、条线、密级和写入等级过滤，再做 Dense+Sparse 混合检索、轻量重排和受限多跳改写；回答携带出处与忠实度检查，证据不足可弃答。
*   **建立工程门禁：** 将架构检查、功能契约、RAG 黄金集、R4/R5/H5/K1/X1 故事负例与单测接入 `run_all`；脱敏黄金集（9 queries、bge-m3-shim）Hit@5=100%、MRR≈0.93、nDCG≈0.95、Faithfulness≈0.93。

**结果：** 内部试点口径下，将会议纪要整理与发送从人工约 20 分钟缩短至约 2 分钟；会后行动项可持续跟踪，高风险写回具备白名单、幂等、HITL 和审计闭环。

**项目四：大模型内容安全控制面** (2025.10 – 至今 | 技术负责人)

**背景：**  
客服 Bot、理财助手等大模型应用面临提示注入、越狱、隐私外泄和高风险工具调用；单纯堆敏感词又会误杀防诈培训、术语解释和密钥轮换等正常业务。我负责建设统一安全网关与策略发布体系。

**核心工作：**
*   **统一在线控制面：** 将输入、模型调用、输出和工具执行纳入 L1–L4 分层防护；安全结果由二元“过/不过”扩展为 `allow / redact / block / confirm_only / alert_only`，支持脱敏放行、仅告警和转人工。
*   **采用规则底座 + 模型插槽：** 高频确定性风险由规则快速拦截，边界语义交给可选远程 Judge；规则命中不能被软模型放宽，并对会话风险、RAG 间接注入和输出外泄分别建控件。
*   **建设 Dual-Gate：** 基于 2400 条期望拦截攻击、100 条正常对照，以及 310/410 条易误杀样本构建攻击门和误杀门；CI、release、full 分层执行，规则变更必须同时满足“应拦不漏、正常不误伤”。
*   **治理策略发布：** publish profile 显式记录本次门禁范围；关键策略双人审批，并在最终签字前重跑当前门禁；SafetyDecision 与审计哈希链支持断链、分叉和篡改检测。
*   **保留私有化边界：** OIDC/JWKS、KMS/HSM、SIEM、远程审核模型的 SPI 适配层与外部红队入口已实现，真实凭据与模型权重外置；外部红队与远程 Judge 未配置时显式跳过。

**结果（脱敏重建环境、静态语料 + shim，可复现）：**  
CI 120 条攻击 + 310 条正常用例通过；release 600 + 410 通过；full 2400 + 410 通过，漏拦与误杀均为 0。该结果用于证明发布门禁可回归，不等同于生产线上零事故。
