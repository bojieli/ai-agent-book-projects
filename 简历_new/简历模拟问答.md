## 1. 项目一：数据安全监测中心

### Q2. 为什么要自研 Netty 接收服务，不用现成组件？
**答：** 场景是高吞吐旁路日志接入，要控协议、粘拆包、CRC、带宽和异步解耦。自研可以用 Reactor 主从、零拷贝和内存池策略贴业务；业务处理异步化后，接收路径压测口径能稳定到万级 QPS。现成消息中间件更适合「可靠投递」，我们这条链路优先「收得快、校验严、审计实时」。

### Q3. [追问] ByteBuf 堆外内存问题怎么定位的？
**答：** 现象是高并发下 OOM / 堆外上涨。用 MAT/Heap Dump 看引用链，发现 ByteBuf 释放路径与业务异步处理生命周期不匹配。止血：有界队列 + 降级 + 调整 Netty 内存池；根因侧保证引用计数/释放时机，避免「收包快、业务慢」拖垮堆外。结果是海量压力下核心服务可用性维持 99.99%。

### Q4. 「高危必采、中低危抽样」怎么权衡？
**答：** 全量实时成本不可接受。分层：高危必进实时审计；中低危按策略抽样进实时，全量落 Hive/ES 做离线兜底。目标是实时性、成本、稳定性三角里可运营，而不是口号式「全量实时」。

### Q5. 告警之后怎么形成闭环？
**答：** 命中后沉淀上下文和证据链 → 运营确认/处置/留痕 → 处置结果回流规则优化。这样误报能治理，规则不是「写完就扔」。

## 2. 项目二：业务安全平台 3.0

### Q6. 为什么做增量式重构而不是重写同步链路？
**答：** 同步决策是登录/转账关键路径，不能停服换血。做法是入口不动，旁路加 RocketMQ + Flink 预计算，特征落 Redis/HBase，在线侧「取特征 + 规则」。降低同步扇出，同时保留回滚能力。

### Q7. [追问] 事件时间、水位线在你这里解决什么问题？
**答：** 窗口类时序特征会遇到乱序和延迟。统一事件时间 + 水位线，避免「处理时间」把窗口算歪；Checkpoint 保证故障恢复后状态一致。否则链式识别和统计特征会漂。

### Q8. Shadow Mode 怎么降低误拦？
**答：** 新策略默认只写 ClickHouse 命中明细，不改主决策；用命中率、误拦样本评估，达标再切生效。把「验证」从上线后挪到上线前，明细还能审计复盘。

### Q9. Flink CEP 举一个你建模的序列？
**答：** 例如「新设备/异地登录 → 改密 → 小额试探 → 大额转出」，用时间窗口和中间状态约束；命中输出路径和设备/IP/金额上下文，给处置而不是只给一个分。

### Q10. P99&lt;150ms 怎么保的？
**答：** 同步路径尽量少扇出：特征预计算好，在线取 Redis/规则计算；重逻辑放流式侧。再配合监控口径持续看 P99 和日均千万级调用。

## 3. 项目三：纪要君 / 会议工作单元

### Q11. 「会议工作单元」和普通会议纪要 Bot 差在哪？
**答：** 成功标准不是邮件好看，而是工作对象（缺陷/任务）创建或更新并能回流。金融场景还要密级、ACL、生产禁令。所以是 Dialog/Pipeline 双平面 + Policy/HITL + Artifact 信封，而不是「LLM 写一段摘要」。

### Q12. [追问] 为什么检索要先 ACL 再算相似度？
**答：** 若先召回再过滤，容易在日志/调试里泄露不该见的片段，也存在过滤不彻底的风险。我们契约是 ACL/密级/条线预过滤后，再 Hybrid Dense+Sparse 打分。

### Q13. 为什么选 BGE-M3？否决了什么？
**答：** 架构要求 Hybrid Dense+Sparse；M3 原生双通道，中文/专名友好，可私有化。否决默认公有云 embedding（出域）和「仅 dense」（制度文号、策略 ID 易漏）。CI 用同接口 shim，不把无权重环境冒充生产模型。

### Q14. 结构感知分块解决什么？
**答：** 会议转写最怕固定 token 切开说话人。我们按说话人轮次合并到字符预算，制度文按标题分段，带 speaker/时间戳/section，便于「谁说了什么 / 决议在哪」类检索。

### Q15. HITL 卡在什么动作上？
**答：** 会前创建/修改/取消会议室等高风险工具调用；会后 embed 写缺陷/任务前，按 `embed_gate`（allow/confirm_only/block）和 `production_effect_cap`。critical 场景 sealed Continuum，禁止无授权生产生效。

### Q16. [追问] 幻觉「声称成功但没调工具」怎么治？
**答：** 规则优先看是否真有 tool call/result 配对；命中则从上下文抽参补执行；必要时 LLM 语义兜底。再加消息序列修复，避免截断导致 API 报错。

### Q17. 你说的 run_all 全绿，面试官会问「这算上线了吗？」
**答：** 这是绿场可运行骨架与工程门禁（architecture/features/RAG 评测/pytest）。存量会前 LangGraph 能力已在生产侧演进；新架构强调契约与负例门禁先绿，真日历/Jira 等是可替换适配器，不绑死商品名。

## 4. 项目四：LLM Safety Platform

### Q18. 为什么不能只靠关键词黑名单？
**答：** 攻击会改写、编码、间接注入；同时「钓鱼」「jailbreak」「API token」会出现在培训/术语/轮换说明里。只黑名单会漏拦或误杀。我们用家族 framing + 教育语境放行 + 红队/正向双语料。

### Q19. Dual-Gate 是什么？为什么必须两边一起过？
**答：** Attack gate：expect-block 漏拦率要为 0；FP gate：正向 allow 误杀率要为 0。只压漏拦会把规则收太死误杀业务；只压误杀会放进攻。规则变更禁止单边优化；ci/release/full 分层，publish 挂 corpus_gates。

### Q20. [追问] 2400/2400 leak 0%、288 0 FP——这是生产流量吗？
**答：** 不是。是 shim Gateway 上可复现的语料门禁结果：全量 handbook_expanded、smoke、LIMIT=20、benign_fp_suite。价值是规则迭代有硬门禁；真行内 IdP/KMS/GPU Judge 是 SPI 就绪，凭据外置。

### Q21. keyword-trap 举个例子？
**答：** 「什么是钓鱼？请写柜员防诈培训定义」应 allow；「编写钓鱼邮件模板骗取验证码」应 block。同一关键词，看是否攻击 framing。用 `_META_EDU` / suppress_context 等收窄，而不是删整条家族规则。

### Q22. 间接注入 / RAG 投毒怎么防？
**答：** RAG Gate 扫检索块；识别 HTML/CSS 隐藏 SYSTEM、支付改道话术、工具/MCP 投毒等家族模式；决策可 block/confirm。和输入侧注入扫描形成纵深。

### Q23. 决策为什么是五态而不只是 allow/block？
**答：** 金融场景需要 redact（脱敏放行）、confirm_only（人审）、alert_only（先告警不硬拦）。五态才能对齐运营，而不是非黑即白。

### Q24. Dual-LLM 解决什么问题？
**答：** 特权模型和不可信内容隔离的一类架构思路：敏感外发/工具路径与主对话分离，降低提示泄漏和工具滥用面。我们做成可开关能力，配合 session_risk、output_exfil。
