## 项目经历

**项目一：数据安全监测中心** (2022.04 – 至今 | 核心开发)

**背景：**  
全行每天有海量安全相关日志（WAF 约 23 亿、管理台操作约 10 亿、消息调用约 600 万）。原来靠事后审计太慢。我参与建设实时监测中心，覆盖敏感信息外传、管理台异常操作、薪资等特敏信息三类场景，目标是不大幅加机器也能跟上数据量——高危必采、中低危按策略抽样，全量离线兜底。

**我做了什么：**
*   多路接入：WAF 旁路采集后按风险抽样进实时审计，其余进 Hive/ES；管理台操作用探针无侵入采集，同样可离线查、可实时搜。
*   自研 Netty 接收服务：单机万级 QPS（压测口径：接收+校验，业务异步做）；处理好粘包拆包和数据完整性。
*   规则引擎做字段级识别与告警；告警带证据，运营能处置，结果能回流改规则。
*   用 Heap Dump 查清高并发下堆外内存泄露，调整内存池策略，核心服务可用性做到 99.99%。

**结果：** 持续拦住多起违规外传和内部泄露风险；资源基本不扩容的情况下撑住数据量增长，线上无重大故障。

**项目二：业务安全平台 3.0** (2024.03 – 至今 | 核心开发)

**背景：**  
App 登录、转账要在返回用户结果前同步给出风控结论。老链路能用，但不太会算“一段时间里的行为序列”，新规则上线也缺少先观察再生效的机制。我在不动老接口的前提下做了增量改造。

**我做了什么：**
*   老入口继续服务；旁边加消息流 + Flink，把特征提前算好放进 Redis/HBase，在线接口主要做“取特征 + 跑规则”，少打一串下游。
*   统一事件时间和水位线，避免乱序把窗口指标算错；Checkpoint 保证挂了能恢复。
*   规则可配置、可下发、可回滚；新规则先影子跑（只记明细、不拦真实交易），看误拦再正式生效。
*   用 Flink CEP 识别多步欺诈，例如：新设备登录 → 改密 → 小额试探 → 大额转出，并把设备、IP、金额等上下文留给处置同学。

**结果：** 同步决策 P99 &lt; 150ms，日均调用 1000 万+；新策略能先用真实流量验证，决策过程可查、可复盘。

**项目三：会议 Agent 平台「纪要君」** (2025.06 – 至今 | 技术负责人)

**问题与边界：**  
行内已有会议预订和纪要能力，但会后建单、行动项跟踪、跨会衔接仍依赖人工。我将成功标准从“生成纪要”调整为“形成结构化会议产物，并在权限、验收与人工确认通过后写回工作系统”。明确不做消费级会议 SaaS、无真实流程的空壳 SOP，以及模型直连外部系统。

**总体架构：**  
控制面负责 `条线 × 场景` 注册、Skill Pack 治理与策略绑定；执行面拆为低延迟对话 Agent 和长任务流水线；记忆/知识面统一管理 Session、Glossary、文档、转写与 Continuum；ToolRuntime 是副作用唯一出口。

**关键设计与落地：**
*   **领域模型与成熟度：** 以 Meeting Work Unit 聚合会议状态、产物、HITL 任务和外部对象回链；Skill Pack 包含目标、成功标准、产物 Schema、策略引用和评测用例。场景按 L0–L3 管理，未知 L0 只能生成草稿，禁止自动写回。
*   **双执行运行时：** 会前采用 Bounded Agent Loop：构造 active-path 上下文 → 按预算发现工具 → Planner 决策 → PreToolUse 权限检查 → 执行 → Observation 回写 → 再决策；生产接真实模型，脱敏工程以确定性 Planner 验证预算/HITL/权限契约。会后采用 Skill Pack 驱动的 SOP / Playbook 状态机，关键验证步骤 fail-closed。
*   **分层记忆与上下文工程：** Session Journal 以追加日志保存消息、工具结果、分支标记和压缩摘要；上下文只沿当前分支恢复，并以确定性摘要压缩旧轨迹。Continuum 保存跨会 open items，写入按 wide/domain/sealed/none 分级；Glossary 只承担短术语消歧。
*   **异步与恢复语义：** 脱敏工程选用进程内调度器 + 协作式取消，优先验证状态、审计和 orphan 恢复语义，不假装具备分布式强杀能力；对话侧可继续查询进度。HITL 恢复时取“当前策略 ∩ 原挂起授权”，避免恢复阶段扩权；会话和任务做对象级授权。
*   **ACL-first RAG：** 文档按标题章节、转写按说话人轮次切块并保留时间戳；召回前按用户、条线、密级和写入等级过滤，再执行 Dense+Sparse、轻量重排与预算内多跳改写；答案携带 citation 和句子级 Faithfulness，证据不足可弃答。
*   **受控写回与质量墙：** ArtifactEnvelope 统一产物元数据；写回必须经过独立验收、HITL、工具白名单、效果上限、幂等键和审计。`run_all` 覆盖架构/功能契约、RAG 黄金集、故事负例与单测；脱敏黄金集（9 queries、bge-m3-shim）Hit@5=100%、MRR≈0.93、nDCG≈0.95、Faithfulness≈0.93。

**结果：** 内部试点口径下，将会议纪要整理与发送从人工约 20 分钟缩短至约 2 分钟；行动项能够跨会衔接并回链工单，高风险副作用具备可挂起、可恢复、可审计的完整路径。

**项目四：大模型内容安全控制面** (2025.10 – 至今 | 技术负责人)

**问题与边界：**  
客服 Bot、理财助手等应用需要统一处理提示注入、隐私外泄、RAG 投毒和越权工具调用；仅靠关键词会造成严重误杀。我负责将分散检测能力收敛为统一在线决策、策略发布和审计控制面。生产 IdP、KMS、SIEM、远程 Judge 通过 SPI 接入，脱敏工程不保存真实凭据和模型权重。

**总体架构：**  
Online Gateway 负责请求/响应扫描与工具调用拦截，Offline 侧负责语料、红队、策略审批和发布门禁；治理台与审计链承接运营和合规。各 Scanner 只提交证据，Policy Engine 输出统一 SafetyDecision。

**关键设计与落地：**
*   **L1–L4 分层防护：** L1 输入扫描（PII、提示注入、会话风险）→ L2 推理前约束（模型/知识/工具绑定）→ L3 输出扫描（外泄、内容与 Schema）→ L4 ToolRuntime 权限与 HITL；五态结果支持 allow、redact、block、confirm_only、alert_only。
*   **规则与模型的职责边界：** 高频确定性风险由规则保障时延和可解释性，边界语义交给可选远程 Judge；严重度只能升级不能被放宽，远程不可用时按 profile 明确 skip 或阻断，不伪造绿色结果。
*   **会话/RAG/工具三类状态风险：** 累计多轮低烈度行为形成会话风险分；检索侧识别间接提示注入和恶意知识；工具执行必须再次经过 allowlist、参数约束和 HITL。
*   **双门发布体系：** 从 YAML 语料计算唯一指标口径，CI / release / full 分层执行攻击 FN 与正常 FP 两道门；publish profile 决定门禁是否启用、跳过或阻断，并将执行结果写入 gates audit。
*   **关键变更治理：** critical 策略采用双人审批，最终签字前重跑当前发布门禁；SafetyDecision 使用公共信封贯穿接口、事件与审计。哈希链按 prev_hash → chain_hash 重建，能识别断链、孤儿、重复、环和分叉，损坏时 readiness fail-closed。
*   **工程边界：** 旧库链字段支持幂等迁移与回填；本地链写入按 single-writer 设计，多副本生产需 advisory lock 或独立 audit writer。外部 garak/PyRIT 和远程 Judge 未配置时显式标记为 opt-in / skipped。

**结果（脱敏重建环境、静态语料 + shim，可复现）：**  
103 项自动化测试通过；CI 120 条攻击 + 310 条正常用例、release 600 + 410、full 2400 + 410 全部通过，漏拦与误杀均为 0。结果用于证明架构和发布流程闭环，不代表生产线上零事故。
