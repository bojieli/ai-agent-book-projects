# 제9장 · 멀티모달리티와 실시간 상호작용

> 인식과 행동의 범위를 텍스트에서 음성, GUI, 물리 세계로 넓힙니다. 세 가지 음성 패러다임(캐스케이드형, 엔드투엔드 완전 모달형, 완전 양방향형), 스트리밍 음성 인식·합성, Computer Use, 로봇 조작을 다룹니다.

← [한국어 메인 README로 돌아가기](../docs/ko/README.md) · 📖 [제9장 본문 읽기](../book-ko/chapter9.ko.md)

## 연계 프로젝트

| 실험 | 프로젝트 | 유형 | 설명 |
| :--: | --- | :--: | --- |
| 9-1 | [live-audio](live-audio/) | ✅ | 음성 인식, AI 대화, 음성 합성을 통합한 실시간 음성 채팅 데모입니다. 여러 AI 서비스 제공자(OpenAI, OpenRouter, ARK, Siliconflow)를 지원하며 지연이 짧은 대화 경험을 제공합니다. |
| 9-2 | [phone-agent](phone-agent/) | ✅ | 사용자를 대신해 전화로 외부 세계와 상호작용하는 음성 에이전트를 보여 줍니다. 상위 계층은 표준 ReAct 에이전트입니다. 자연어 작업을 받으면 통화 횟수와 목적을 스스로 정하고, 통신 API 추상화 기반 `make_phone_call` 도구로 전체 대화를 수행합니다. 구조화된 통화 기록을 읽고 필요하면 다시 전화해 후속 질문을 한 뒤 최종 결과를 사용자에게 보고합니다. |
| 9-3 | [streaming-speech](streaming-speech/) | ✅ | 스트리밍 음성 인식의 핵심 절충을 보여 줍니다. 연속 음성을 점점 길어지는 구간으로 나누어 ASR에 입력하고, 구간을 받을 때마다 ‘현재 부분 인식 결과’를 출력해 첫 구간의 텍스트를 매우 짧은 지연으로 제공합니다. 다만 초반 구간에는 문장 후반의 맥락이 없어서 오류가 날 수 있고, 음성이 누적될수록 결과가 점차 수렴합니다. 이는 ‘문장 전체를 기다린 뒤 인식’하는 고정확도·고지연 방식과 대비됩니다. |
| 9-4 | [end-to-end-speech](end-to-end-speech/) | ✅ | Step-Audio R1의 엔드투엔드 음성 사고(‘듣기 → 생각하기 → 말하기’)를 구현하고, ASR→LLM→TTS 캐스케이드와 지연 시간 및 준언어 정보 손실을 비교합니다. |
| 9-5 | [controllable-tts](controllable-tts/) | ✅ | 주 LLM의 출력에 감정·말하기 속도·스타일·멈춤·웃음 제어 토큰을 포함합니다. 실행 계층은 이 토큰을 해석해 참조 음성 라이브러리의 스타일 프로필에 대응시킨 뒤 음성을 합성합니다. ‘어디서 멈추고 어떤 어조로 말할지’에 대한 결정을 LLM에 맡겨 같은 텍스트도 서로 다른 스타일과 감정으로 합성할 수 있습니다. |
| 9-6 | `claude-quickstarts/` | 📖 | 다양한 사용 사례를 다루는 Claude API 빠른 시작 예제와 모범 사례입니다. |
| 9-7 | `browser-use/` | 📖 | Browser-Use는 LLM이 브라우저를 제어해 복잡한 작업을 완료하게 하는 강력한 브라우저 자동화 프레임워크입니다. 양식 작성, 웹 탐색, 데이터 추출 같은 시나리오를 지원하며 GUI 자동화(Computer Use)의 대표적인 구현입니다. |
