用程序强制执行工具预算

把“最多调用二十次”从一句提示词，变成模型无法绕过的 Python 规则。

  • 已掌握：工具消息必须配对
  • 本课只学：执行前预算检查
  • 本课胜利：能让循环安全收尾
本课唯一结论：模型负责请求工具；Harness 必须在行动发生前决定“能不能执行”。

提示要求不等于硬约束

系统提示可以告诉模型“最多调用二十次”，但模型仍可能发起第二十一次请求。真正的上限必须由程序计数。检查要发生在工具执行之前，因为网络请求、付款和文件修改都不能靠事后统计撤销。

  1. 模型请求工具
  2. 程序检查预算
  3. 执行或拒绝
  4. 回答并结束

把规则放进最小循环

MAX_TOOL_CALLS = 20
used_calls = 0

while True:
    reply = call_model(messages, allow_tools=True)
    messages.append(reply)
    calls = reply.tool_calls or []

    if not calls:
        return reply.content

    # 一次并行请求也要按总数在执行前检查
    if used_calls + len(calls) > MAX_TOOL_CALLS:
        for call in calls:
            messages.append(tool_result(
                tool_call_id=call.id,
                content="未执行：工具预算已用尽",
            ))

        # 保留已有工具结果，但不再提供工具能力
        final_reply = call_model(messages, allow_tools=False)
        return final_reply.content

    used_calls += len(calls)  # 失败的实际调用也占用预算
    for call in calls:
        result = execute_tool(call)
        messages.append(tool_result(call.id, result))

拒绝一批调用时，仍需为每个 call.id 写回一条结果。这样既保持消息顺序合法，也让模型知道工具没有执行。收尾调用保留历史证据，但关闭新的工具能力。

只剩一次额度，却请求三个工具

三个调用已拒绝写回三个对应结果不能丢失调用编号
进入收尾模式禁用工具并生成回答不能继续拒绝—重试
