读懂一次工具调用的消息记录

把上一课的“搜索 → 返回结果 → 再判断”翻译成模型 API 真正收到的消息列表。

  • 已掌握：工具结果必须回传
  • 本课只学：四种消息角色
  • 本课胜利：能补全缺失消息
本课唯一结论：assistant.tool_calls 是模型发出的“请调用工具”请求；tool 消息才是程序执行后的真实结果。

先认识四种角色

开发者写规则

“至少比较两个独立可靠来源；最多搜索三轮。”

用户提出任务

“查清楚咖啡是否影响睡眠，并给出来源。”

模型决定下一步

请求调用 search_web，参数是搜索关键词。

程序送回真实结果

三条搜索结果：标题、链接、来源、日期和摘要。

下一次模型调用时，程序会把以上消息全部再次发送。模型 API 自己不会保留上一次调用的记忆。

看懂请求与结果如何配对

{
  "role": "assistant",
  "content": null,
  "tool_calls": [{
    "id": "call_search_7",
    "function": {
      "name": "search_web",
      "arguments": "{\"query\": \"coffee sleep evidence\"}"
    }
  }]
}

{
  "role": "tool",
  "tool_call_id": "call_search_7",
  "content": "[{\"title\": \"...\", \"url\": \"...\"}]"
}

tool_call_id 与上面的 id 相同，表示“这份结果回答的是这次调用”。如果模型一次请求搜索和读取两个工具，就会产生两个不同的 ID，结果不能串错。

不要把模型当成执行器

动作负责人原因
选择工具和参数模型这是决策
校验参数和权限Harness不能盲信模型请求
访问真实网页工具这是外部行动
追加工具结果Harness为下一轮提供观察
